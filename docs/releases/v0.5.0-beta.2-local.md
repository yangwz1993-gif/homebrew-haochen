# haochen 0.5.0-beta.2 · 本地验收候选

本轮只在本机安装测试，不是公开 Release，不更新 Homebrew。沿用稳定本地自签名的 legacy DMG，未经 Apple 公证。

## 这次改变

- 刘海下沿显示待确认、异常、新结果、处理中的轻量状态；桌宠仍可打开同一个总览或独立对话。
- 总览在前台时 ⌘M 收回刘海；无刘海显示器使用顶部胶囊。收起再打开保留当前内容、草稿和滚动位置。
- 总览使用普通窗口层级；打开来源后让出前台。详情、日报和设置使用一致的浮窗；Esc 逐层返回。
- 首页明确显示连接状态，Otty/Chrome/微信不再因为尚未接通而从页面上消失。
- 已读与内容版本绑定，旧回执不清除新动态。看过待确认或异常内容只清未读徽标，不代表问题已经解决。
- 正常 Agent 不再继承其他 Agent 的未连接说明；无语义变化的轮询不重建当前详情。

## 各来源的实际边界

**Otty**：读取官方 CLI 当前状态和精确终端标识。Pi/OMP 可先查看安装方案，再明确确认添加 Otty 官方集成；不覆盖文件、不重启既有会话。其他 Agent 按官方设置引导。已实测真实 Pi 的 processing → idle 及精确 pane 跳转。约 3 秒快照不是完整事件流，不能保证捕获两次检查之间已结束的短暂状态。

**Chrome**：打开连接向导，加载本包配套扩展、完成本机桥接，再由用户逐站授权并选择追踪页面。读取授权标签的 DOM 正文，返回来源只定位原绑定标签，不偷偷改开其他网页。尚未在用户 Chrome 中完成授权的步骤必须继续显示待连接，不能当成真实站点已验证。

**微信**：可按需观察公开 Dock 未读标记并打开微信，不读取聊天正文、不定位单聊、不读取私人数据库。未暴露标记时未读数为未知，不视为零。需要一条用户自己发送的测试消息完成正向来信验证。

**日历**：保持用户显式连接与选择范围；日程改期（含仅结束时间改变）触发新内容版本，打开日程详情可回执已读。飞书仍延期。

## 本机安装与用户数据

- 安装目标：`/Applications/haochen.app`。
- 新包：`packaging/dist/haochen-0.5.0-beta.2.dmg`（dist 指向 dist.noindex）。
- 最终包大小 79,033,338 bytes；SHA256：`53e7d078a09b11734ef25037179a341068ef14bcd2608ec745e644bd72ebd985`。已从这个 DMG 替换安装并启动。
- 旧 App 放进废纸篓，可恢复；旧 DMG 挂载盘会推出，不留下第二个挂载应用。
- 不清空模型配置、会话、日志、Keychain 或 TCC。已有模型 Key 仍可能需要用户亲自完成 macOS 钥匙串授权；本轮未代替用户授权，不反复请求。

## 你可以这样验收

1. 从刘海或桌宠进入总览，查看状态、打开详情；⌘M 收起后再恢复，检查位置与草稿。
2. 让一个已装官方集成的 Otty Agent 工作，检查状态与来源跳转；另外一个未配置 Agent 不应污染其提示。
3. 从文件条打开一个已有文件夹，Finder 应出现在总览上面；不应被总览压住。
4. 完成 Chrome 明确授权后，修改测试页内容并返回原标签；未经授权的网页不应出现在动态里。
5. 用手机给文件传输助手发测试消息，暂不在电脑点开，核对 Dock 标记与总览状态。
