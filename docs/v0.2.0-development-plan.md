## 1. 产品理解

haochen 是一个独立的 macOS 技术 Agent：以常驻桌宠作为轻入口，以对话气泡和完整聊天窗口承载任务，通过 JSONL RPC 驱动 Bun 打包的 pi 引擎，并提供配置、会话、读屏、工具调用和 DMG 分发能力。

核心体验应满足四点：

1. **开箱可用**：首次启动能够完成模型配置、连通性验证和按需授权；
2. **过程可信**：思考、工具执行、等待确认、失败和恢复状态都可见；
3. **数据安全**：Key、屏幕内容、会话和签名凭据不会越权、泄露或意外丢失；
4. **macOS 原生**：菜单栏、快捷键、窗口、多屏、权限和签名公证符合平台习惯。

## 2. 当前架构与基线

- `app/haochen_app/app_shell.py`：应用编排、首次启动、三个 UI 的协调；
- `app/haochen_app/engine_client.py`：引擎进程和 RPC；
- `app/haochen_app/supervisor.py`：健康检查、崩溃重启、会话恢复；
- `app/haochen_app/chat/`：完整聊天、会话列表、流式消息和工具卡；
- `app/haochen_app/pet/`：桌宠与气泡入口；
- `app/haochen_app/settings/`：模型和认证配置；
- `app/reader/haochen_reader.py`：屏幕/页面读取；
- `pi-source/`、`engine/`：pi fork 与 Bun 单文件引擎构建；
- `packaging/`、`cask/`：App/DMG/Cask 分发；
- `mock-engine/`、`tests/`、各模块 `verification/`：现有回归资产。

现有协议、模型隔离、三 UI、真引擎集成和 DMG 打包已经打通；当前主要问题不是重写架构，而是补齐安全边界、生命周期、可恢复交互和可发布工程体系。

## 3. 审计发现

### P0：已确认缺陷与安全问题

| 问题 | 证据位置 | 修复方向 | 验收标准 |
|---|---|---|---|
| 删除会话可删除会话目录外的任意路径，且 UI 吞错 | `engine_client.py:219-220`、`chat/window.py:585-600` | 路径 canonicalize + 根目录约束；删除移至 Trash/可撤销；错误可见 | `..`、软链接、绝对路径越界测试全部拒绝；失败不丢当前会话 |
| 切换/新建后 supervisor 仍保存旧恢复路径 | `supervisor.py:197-202`、`chat/window.py:550-563` | 会话状态由单一 SessionCoordinator 管理并在切换成功后原子更新 | A→B 后杀引擎，恢复 B；切换失败仍留在 A |
| 退出在 Qt 主线程最多阻塞 3 秒 | `engine_client.py:106-113` | 异步 shutdown；terminate→超时→kill→wait/join | 忽略 SIGTERM 的假引擎下 UI 不冻结，进程无残留 |
| 旧工程包含签名私钥、P12 和明文口令 | `haochen_new/packaging/signing-*` | 立即轮换/吊销；新仓库只接受 Keychain/CI Secret 注入 | Git 历史和发布包无私钥；secret scan 通过 |
| 读屏 URL 可读取 `file://`，并存在 SSRF 风险 | `reader/haochen_reader.py:407-416` | 仅允许 HTTPS；DNS/IP/重定向逐跳校验；限制大小与 MIME | file、本机、私网、link-local、超大响应全部拒绝 |
| 提问/日志权限过宽，敏感文本落盘 | `app_tracking.py:55-63` | 默认不记录正文；目录 0700、文件 0600、原子写；提供清除入口 | 新装权限测试通过，日志不含完整 Key/提问/屏幕正文 |
| Cask 递归清除 quarantine，App 未正式公证 | `cask/Casks/haochen.rb:14-18` | 删除绕过逻辑；Developer ID + hardened runtime + notarize + staple | `codesign`、`spctl`、`stapler validate` 全通过 |

### P1：稳定性和体验缺口

- RPC 缺少请求超时、pending 清理、坏 JSON 诊断和 stderr 日志轮转；
- 首启同时弹多个权限页面，Key 明文保存且没有“保存并验证”；
- 对话 delta 每次全量 Markdown 重绘并强制滚底，回看体验差；
- 大窗口和气泡对“生成中追问”的行为不一致，崩溃会丢排队输入；
- 工具卡缺少等待确认、取消、重试、耗时和产物入口；
- LSUIElement 模式缺少完整菜单栏入口、`⌘,`、About 等原生能力；
- 自动化测试偏脚本断言，缺少 pytest、静态检查、覆盖率和发布门禁。

### P2：完善项

- VoiceOver 名称、纯键盘操作、减少动态效果、200% 缩放；
- 多屏气泡定位、窗口尺寸记忆、桌宠贴边/隐藏/降打扰；
- 消息与代码一键复制、Token/耗时信息和历史搜索。

## 4. 实施方案

### 阶段 A：工程基线与安全止血

1. 建立 `pyproject.toml` 和锁文件，固定 Python/PyQt/PyInstaller；保留 pi 的 lockfile；
2. 统一读取根目录 `VERSION`，让 App、DMG、引擎和 Cask 版本一致；
3. 增加 secret scan、ruff、mypy/pyright、pytest 和 shellcheck；
4. 移除 Cask quarantine 绕过，替换签名注入方式；
5. 修复路径删除、SSRF、本地权限和敏感日志问题。

**完成门槛**：P0 安全测试全绿；仓库和构建产物扫描无 secret；任何失败均阻止打包。

### 阶段 B：引擎与会话可靠性

1. 把进程启停移出 UI 主线程，定义启动、运行、降级、重启、退出状态机；
2. RPC 请求加入 ID、超时、取消和 pending 清理，stderr 写入脱敏轮转日志；
3. 建立 SessionCoordinator，统一大窗、气泡和 supervisor 的当前会话；
4. 排队输入持久到本地草稿，崩溃后可恢复、取消或重发；
5. 增加挂死、半行 JSON、错误事件、SIGTERM 无响应、连续崩溃熔断测试。

**完成门槛**：切换会话后崩溃恢复正确；退出无卡顿/孤儿进程；引擎失联时用户总能看到状态和恢复动作。

### 阶段 C：关键交互重做

1. 单一首启向导：欢迎 → Keychain 存储并验证 → 按需权限 → 首次试问；
2. 统一双入口消息队列，并展示顺序、取消和失败重试；
3. 流式渲染节流，仅当用户位于底部时自动跟随，并提供“回到最新”；
4. 工具卡采用统一状态：待确认/运行中/成功/失败/取消，支持取消、单步重试和打开产物；
5. 删除会话二次确认并提供撤销，所有不可逆操作明确反馈；
6. 增加菜单栏入口和标准快捷键。

**完成门槛**：首次启动不出现并发弹窗；输入、会话和工具状态不会静默丢失；大窗与气泡行为一致。

### 阶段 D：无障碍、视觉与发布

1. 补齐 accessible name、焦点顺序、键盘菜单和 Reduce Motion；
2. 完成多屏定位、窗口记忆、桌宠贴边和降打扰；
3. Developer ID 签名、公证、staple 和干净机器安装；
4. 执行 L1 单元、L2 RPC、L3 UI、L4 打包、L5 干净系统验收。

**完成门槛**：VoiceOver/键盘主流程可用；`spctl` 接受；升级安装保留用户配置且可回滚。

## 5. “修复所有 bug”的闭环定义

“所有”不以口头保证定义，而以可审计门禁定义：

- 当前清单中的 P0/P1 全部关闭且每项有回归测试；
- issue 使用“复现 → 失败测试 → 修复 → 通过证据 → 关闭”的流程；
- 单元/RPC/集成/打包/权限/安全测试全部通过；
- 无未解释的崩溃、数据丢失、主线程长阻塞、高危安全发现；
- P2 若不阻塞发布，必须进入里程碑并在 release notes 明示，不能静默遗漏。

## 6. 版本与分支管理

- 采用 SemVer：当前 `0.2.0-dev.1`，候选版 `0.2.0-rc.1`，验收后 `0.2.0`；
- `main` 只保存可发布状态，日常开发在 `develop`；每个问题使用 `fix/<issue>`，体验改进使用 `feat/<issue>`；
- 提交采用 Conventional Commits，例如 `fix(session): reject paths outside session root`；
- 每次提交只解决一个问题，并同时提交测试和 CHANGELOG；
- RC/正式版使用 signed tag；构建产物附 SHA-256、签名和公证证据；
- 发布失败从 tag 回滚，不在已发布 tag 上补写；热修复递增 patch 版本。

## 7. 测试与质量门禁

本地和 CI 至少执行：

1. Python：格式、lint、类型、单元测试、覆盖率；
2. RPC：mock 契约、真引擎 smoke、超时/崩溃/错误输入；
3. 安全：路径穿越、软链接、SSRF、权限、日志脱敏、secret scan；
4. UI：首启、流式滚动、双入口队列、会话恢复、工具取消/重试；
5. 发布：版本一致性、依赖可复现、codesign、notary、staple、DMG 安装与升级。

P0 模块目标覆盖率不低于 90%，项目整体不低于 80%；覆盖率只是底线，关键场景必须有行为测试。
