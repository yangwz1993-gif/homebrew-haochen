# 经验与坑 — haochen

- PyObjC 选择器多下划线（updateTrackingAreas_）→ 刘海/总览点击无反应 → 影响：原生层改名后必跑类创建探针测试 [已解决 1cd4695]
- 已解压 Chrome 扩展不热重载 → untrack 命令旧扩展不认识 → 影响：扩展协议变更要版本握手+提示用户刷新 [部分，B-16]
- 启动弹窗抢键盘焦点会撕碎输入法组词 → 影响：任何自动弹出不许 activate [已解决 857462e]
- hi CLI 无未读/私聊接口 → 私聊未回只能推断式并如实标注 → 影响：不许在 UI 写「精确未读」
- citylink 跳转带 host 会被 Hi 改写致路由失效 → 影响：跳转 URL 永远不带 host
- Python 模块命名撞标准库（如 io 永远命中标准库，本地同名模块被静默绕过）→ 影响：模块命名避开标准库名，建房（scaffold/新建模块）时先检测撞名
- 2026-09-17：日常迭代装到 /Applications 的包也必须用 `HAOCHEN_BUILD_MODE=legacy`（稳定自签 haochen Local Signing）。development 模式是 adhoc 签名，每次重打包 cdhash 都变，TCC 权限（辅助功能/屏幕录制）全部失效——用户读屏整条链路直接挂掉。release-checklist 早有明文，迭代场景同样适用。
- 2026-09-17：WKWebView 的完成回调（getAllCookies 等）跑在 WebKit 自己的 IPC 线程，回调里碰 AppKit/Qt（window.close 等）直接 SIGABRT 崩掉整个 app。规矩：回调里只发 Qt 信号，收尾经 QueuedConnection 回主线程。删除 cookie 的选择器是 deleteCookie_completionHandler_（deleteCookie_ 是错的）。验证方式：本地起 HTTP 服务种 cookie，真开窗端到端跑一遍。
