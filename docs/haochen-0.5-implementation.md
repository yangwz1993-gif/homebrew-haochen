# haochen 0.5 · 本机可用里程碑

目标：在已验收的 0.3.4 上增加真实桌面总览，不替换稳定的桌宠、模型设置和读屏链路。先交本机验收，不发布 Release 或 Homebrew。

## 范围与接入约束

- Otty：官方 CLI 元数据、Agent 生命周期、精确跳转；未安装官方集成时明确“状态未知”，不猜完成。
- 浏览器：配套 Chrome 扩展，用户逐站授权并主动选择追踪页；原始 DOM 优先，不自动读全部标签页。
- 日历：用户主动授权后读取同步至 macOS 的日历；可选择范围，不改写事件。
- 文件条：用户拖入/选择后保存本机入口；移除引用不删除原文件。
- 事项：用户自建，渠道与频率显式设置；独立刷新、来源证据、检查时间、失效状态。AI 摘要需要用户选择，不能自动宣布事项完成。
- 日报：可见入口、历史日期、真实变更和待处理事项；未运行期间无观测则明确缺失，不补造历史。
- 飞书：按用户本轮要求延期。
- 个人微信：没有可靠公开全量消息接口；明确受限，不伪造连接或抓取私人数据库。

## 实现顺序

1. 原生 NSPanel / WKWebView 与现有 Qt 事件循环共存，验证中文输入、Esc、开合和退出。
2. 移植确认的视觉：浅雾绿默认、动态/事项/日报统一液体浮窗、文件条、独立全局桌宠。
3. 数据模型、私有持久化、有界后台任务、真实 Otty / Chrome / 日历适配器。
4. 追踪刷新与证据日报，AI 工作与用户当前会话隔离。
5. 权限缺失/离线/多屏/重启/空态/大量信息/减少动态效果回归。
6. 构建 0.5 本地预览 DMG，检查冻结依赖和版本；用户验收后再决定发布。

## 不可退让的边界

- 不清空用户日志、配置、Keychain 或 TCC，不自动安装浏览器扩展/Agent hooks。
- 不把透明全屏 WebView 当桌面：原生窗口只占面板实际边界，收起后仅保留小入口。
- 网页到原生仅白名单 JSON 动作；无任意 shell、文件读取或 JavaScript 执行接口。
- 来源失效保留“过期”标注，不将失败记作“没有变化”。
- 自动摘要不读取项目提示文件、不调用工具、不写用户会话、不上传用户未选择的渠道。
