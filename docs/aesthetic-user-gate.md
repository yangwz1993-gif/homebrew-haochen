# 独立审美用户验收门禁

这道门禁用于所有直接影响用户观感和操作体验的版本。它不能替代自动化测试，
也不能由参与该功能设计或编码的人自行通过。

## 角色边界

独立审美用户只拿到：

- 可运行的 App 或安装包；
- 一组以用户口吻描述的使用任务；
- 必要的测试账号、隔离数据和安全说明。

该角色在首次审视前不得阅读实现代码、PR、设计理由、问题清单或开发规划，避免被
已有解释锚定。它不修改代码和素材，只记录真实使用时看到的问题。

## 固定体验场景

每个体验里程碑完成后，至少实际走完：

1. 第一眼看到桌宠，唤起并收起小窗；
2. 输入短问题，观察接单、处理、工具、整理和结果呈现；
3. 阅读短答，继续追问，再展开和收起详情；
4. 体验长文本、换行、窗口边缘、多屏或空间不足状态；
5. 停止生成、拒绝权限、错误恢复；
6. 开启“减少动态效果”后的静态体验。

审视维度包括第一印象、人物与气泡关系、轮廓、排版、留白、信息层级、按钮、动效
节奏、原生感、可理解性和不打扰程度。

## 两阶段审视，避免遗漏和诱导

### 第一阶段：盲测

只按用户任务自由使用，不提供现有问题、设计目标或参考截图。先记录第一眼就能发现的
问题，避免验收者顺着开发者给出的答案检查。

### 第二阶段：状态矩阵与参考差异

盲测提交后，再逐项检查输入、接单、授权、执行、整理、结果、错误、停止八种状态；
最后才提供用户反馈截图做差异检查。第二阶段发现的问题要单独标记，不能混成“盲测时
已发现”。

每个状态必须截取**人物和气泡的联合画面**，不能只截气泡控件，否则无法判断遮挡、
尾巴指向和桌面关系。相同状态至少保留一张空内容或短内容截图；结果态增加长中文截图。

## 强制测量

验收不能只使用“有点空”“不协调”等形容。每个状态至少记录：

- 气泡矩形：`x / y / width / height`；
- 人物矩形，以及气泡底部到人物顶部的距离；
- 尾巴尖到人物中心的水平偏差；
- 标题、正文、输入框或按钮之间的主要垂直间距；
- 最大连续无内容区域的高度，以及它占气泡主体高度的比例；
- 点击到界面反馈、状态切换和退场的大致耗时；
- 是否发生裁切、滚动条、跳位、闪烁、遮挡或点击结果与按钮文案不一致。

小窗基线：人物与气泡间距应为 `6–10px`，尾巴对人物中心偏差不超过 `4px`；输入态
不得出现超过 `24px` 的非设计性连续空白，结果态底部非设计性空白不超过 `16px`。
超出基线必须明确报告具体数值和截图编号。

## 输出格式

问题必须按严重程度排列：

- `阻断`：无法完成核心任务，或体验明显失控；
- `明显瑕疵`：普通用户会立即注意并降低信任；
- `精修项`：不阻断使用，但影响高级感和一致性。

每项使用固定字段：

- `证据编号`：对应截图或录屏；
- `状态与操作`：从干净状态开始的最短复现步骤；
- `实际`：看到的具体控件、位置和行为；
- `测量`：矩形、间距、空白比例或耗时；
- `预期`：用户能直接判断的正确反馈；
- `影响`：为什么妨碍理解、信任或操作；
- `严重度 / 置信度`：严重度按下述三级，置信度为高、中、低；
- `复验点`：修复后只需执行的一条验证动作。

宽泛的“再美化一下”“留白不协调”不算有效反馈；无法测量时必须写明限制，不能把
推测写成事实。

## 通过规则

开发者完成实现和自动化验证后，才触发独立审美用户验收。存在 `阻断` 或 `明显瑕疵`
时，该体验里程碑不得标记完成。问题由开发者修复后，必须重新提供可运行产物，由独立
审美用户复验；开发者不能替代复验结论。

流程固定为：

`实现 → 自动化验证 → 构建隔离试用包 → 独立体验 → 修复 → 独立复验 → 阶段完成`

每轮验收使用 [`aesthetic-user-test-brief.md`](aesthetic-user-test-brief.md)；该任务单不含
实现方式和已知缺陷，确保验收角色保持独立。
