# v0.3.4-rc.5：配置保存到引擎就绪的统一流程

日期：2026-09-11。范围为一期初始化填写后不生效的问题；不进入二期，不更新线上 Release 或 Homebrew Cask。

## 根因与修复

引擎在填写 Key 之前已经启动；凭据通过子进程环境加载，仅保存钥匙串和配置不会刷新正在运行的引擎。旧首启流程只有自定义服务重启引擎，DeepSeek 预设仅发送模型切换后直接试问。真实日志中失败后重启才出现正常回答，与代码路径一致。rc.4 的按钮统一没有覆盖此整链路。

首启、重新连接、更换 Key、自定义服务和设置切换模型现在共用配置生效协调器：

1. 验证并保存 Key 和配置，锁定连接操作及新消息发送。
2. 等待正在进行的回答完成，不强制中断当前工作。
3. 需要时自动重启引擎以加载新环境，恢复已持久化会话。
4. 等待模型切换 RPC 成功，再查询引擎状态核对实际 provider / model。
5. 只有就绪后显示连接成功、解锁发送、完成首启并发出试问。

失败保留已保存配置，并阻止旧状态继续发送；用户可通过同一个连接按钮重试，无需重新填 Key。仅切换已有模型时无需重复重启，但仍等待确认。首次向导直接续办到试问页时也执行就绪检查，取消向导不会由迟到回调发送试问。
