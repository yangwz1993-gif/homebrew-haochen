# v0.3.3 Keychain hotfix 独立用户验收 02

## 裁决

**PASS。**

第 1 轮的两个阻断均已在新的冻结候选中真实复验通过：

- DeepSeek 升级用户会直接在 haochen 内看到“为避免旧版钥匙串弹窗，请在这里重新输入一次 API Key 并验证”，不用猜为什么要重填；

## 用户视角结论

这次修复终于把“系统为什么突然要钥匙串密码”从一个无法理解、无法关闭的 macOS 弹窗，变成了 haochen 自己能解释、能关闭、能继续操作的页面。对普通 DeepSeek 用户，下一步非常明确；对自定义模型用户，原 URL 和模型信息没有丢，重填成本被压到只剩一个 Key，符合升级预期。

视觉上，升级说明紧邻验证按钮且不拥挤；自定义模式增加到四个输入项后仍全部落在 680 × 580 的首屏内，没有裁切、重叠或滚动才能找到 Key 的问题。按钮层级与既有米白、深绿、黑色描边体系一致。

## 非阻断建议

- 当前文案已经足以完成任务。后续若继续润色，可补一句“旧 Key 不会被读取或删除”，进一步减少重视隐私用户的疑虑；不影响本轮放行。
- “Keychain”与“钥匙串”在不同页面混用，后续可统一为用户更熟悉的“macOS 钥匙串”。
- 设置页多层粗描边的视觉重量仍偏重，可纳入后续整体视觉升级，不应扩大本次 hotfix 范围。

## 覆盖限制与清理

- 按安全边界，本轮没有输入或发送真实 API Key；成功联网回答沿用冻结候选的 372 项检查与 6/6 回归证据，本轮重点以真实 UI 验证升级/失败前置路径。
- 两个候选进程均已结束；没有遗留 haochen 或测试 engine 进程。
- 隔离 Keychain service 中没有写入凭据。

**最终结论：PASS，可以进入 PR / CI 与 legacy DMG、Homebrew 发布复核。**
