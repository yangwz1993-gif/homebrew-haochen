# 0.5.0-beta.3 真实连接验收

本轮由用户明确允许安装 haochen 配套 Chrome 扩展并测试本机网页。仅本地候选，不公开发布，不更新 Homebrew。

## beta.2 实机定位与后段链路证据

- Chrome 实际加载 `/Applications/haochen.app/Contents/Resources/browser-extension`，固定 ID `hjbiopmhlpcnpaojialipdhdemnafecb`。用户原有扩展与网页未修改。
- 从已安装 haochen 的连接界面注册本机桥接；Chrome 扩展显示已连接。
- 仅授权 `127.0.0.1` 站点，实际追踪一个独立临时测试页。Chrome 权限按站点而非端口授予；扩展仍只读取用户明确绑定的精确标签与网址，不追踪同站点其他页面。
- 第二次点击追踪后收到真实正文，未采集输入框内的排除测试值。此结果验证后段读取，但不掩盖首次授权缺陷。
- 点击测试页自身按钮改变正文后，同一 source/tab/window 保持；指纹更新、旧正文消失，输入框仍被排除，总览记录 `available` 且 `unread=true`。
- 从安装版点击“打开来源”，本机桥接收到 Chrome 的 `focused` 回执；目标来源、标签、窗口和网址均为该测试页，不是重新打开同网址冒充精确跳转。
- 实际切到同服务第二页后，原来源为 `target_changed`、正文清空、`coverage=none`；第二页没有自动加入来源。随后从扩展界面移除本次测试来源，并撤回测试站点自动访问。

## 本轮实机发现的缺陷

1. 扩展小窗串行等待 `permissions.request` 再发起追踪；Chrome 原生授权框使小窗销毁后，后半段丢失。表现为站点已授权、追踪列表仍为 0。
2. 总览状态文案缺少 `available` 等连接器实际状态，导致已真实读取的网页仍显示“状态未知”。

上述正文更新、精确跳转及切页保护是 beta.2 实装记录；下述 beta.3 复测专门验证首次授权修复，不混淆两次安装的测试范围。

## 修复与自动化范围

- 扩展后台持有一条有界、非持久的精确页面选择，在收到小窗点击消息的同步回调内调用 Chrome 权限请求；用户手势与原生请求结果都归属后台，不靠其他授权事件推断同意。
- 拒绝、显式取消、60 秒超时、页面导航/关闭/替换、权限撤回、后台重启均不得恢复旧选择；绑定前重新核对精确标签、窗口、网址和授权。
- 11 项 Node 授权事务测试直接运行生产 popup/background 脚本，模拟小窗在授权中销毁及以上边界；已纳入 `make check`。
- Dashboard Node 31/31、真实隔离 WK 76/76 已通过。另在隔离真实 WK 中确认浏览器“已读取页面文字”和微信“已获取未读标记”可见，无裁切；微信这项是隔离测试，不代替真实来信验收。

## 微信与模型边界

- 用户已发测试消息，但微信 Dock 项目的 `AXStatusLabel` 返回 `kAXErrorNoValue`；辅助功能权限通过且对象精确匹配，不是权限失败或数值解析失败。
- 已通过 haochen 界面开启微信观察，安装版如实显示“标记暂不可读”。不能据此认定消息没收到、未读为零或已完成正向提醒验收。
- 不读取微信聊天数据库或通知档案；不擅自打开聊天清除未读。
- 模型钥匙串窗口需要用户本人完成。代理不操作受保护的系统授权窗口，不记录或使用聊天中提供的系统密码。
