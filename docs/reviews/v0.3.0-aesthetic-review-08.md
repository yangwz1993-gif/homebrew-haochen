## 最终裁决：NOT PASS

本构建存在 5 项仍可稳定感知的“明显瑕疵”，未达到“明显瑕疵清零才可 PASS”的门禁条件：普通完整对话窗会以异常小尺寸恢复；最大化后桌宠遮挡输入与发送区；完整对话重复显示同一答案；信息不足问题擅自检查无关工作目录且回答冗长；明确要求“最多两点”的技术简答仍重复结论并展开五项以上内容。

未发现阻断级崩溃。无凭据错误泄漏、详情打开/追问/收起、读屏拒绝隔离等关键复验项在本轮可见结果中通过，但不能抵消上述明显瑕疵。

## 环境校准与证据有效性

每次均直接启动 App 内可执行文件，启动前清理旧 `haochen` 实例，并核对只有一个实例。会话文件仅写入当次 `HAOCHEN_HOME` 对应的隔离目录。

首次所谓“有效目录” `/private/tmp/haochen-qa-round8-valid.AreHsm` 的 `auth.json` 实为模板占位，未绑定 Keychain；A03 中的 `invalid authorization` 是测试夹具遗漏，不是产品结论。A03 仅保留为环境作废记录，完全排除于缺陷、复现率及裁决之外。切换到已绑定非敏感 Keychain 环境引用的 `valid2` 后，真实模型问答与读屏均可完成。

自由盲测观察已先行封存于 `blind-observations-sealed.md`。其中涉及 A03 的观察按后续环境校准作废，其余观察未回写修改。

## 真实缺陷

### D01 普通完整对话窗恢复为异常小尺寸，内容严重裁切

- 状态：未修复
- 操作：在结果中进入详情，完成追问并收起；随后从菜单打开普通完整对话窗。
- 实际：窗口恢复为约 `380 × 200 pt` 的狭小尺寸，正文、会话控制、底部模型与输入区同时被挤压或裁切，无法形成正常完整对话工作区。
- 预期：普通完整对话窗应恢复到可读、可操作的合理尺寸；正文、输入、按钮与模型信息均不应异常裁切。
- 影响：用户无法舒适阅读和继续对话，且第一眼很像窗口状态损坏。
- 严重度：明显瑕疵
- 置信度：高
- 复现次数：1/1（按“详情收起后再打开普通完整窗”路径）
- 截图编号：A22

### D02 最大化普通完整对话窗时，桌宠遮挡输入框和发送区

- 状态：未修复
- 操作：将普通完整对话窗最大化，继续输入与发送问题。
- 实际：桌宠保持在最上层并覆盖窗口右下角，明显压住底部输入框右段及发送按钮区域；输入虽可借助键盘继续，但关键控件被遮挡。
- 预期：完整对话窗显示时，桌宠不应覆盖输入、发送或其他主要操作控件；至少应自动避让或降低层级。
- 影响：直接妨碍连续追问，破坏窗口层级可信度。
- 严重度：明显瑕疵
- 置信度：高
- 复现次数：2/2
- 截图编号：A23、A24

### D03 完整对话中同一短答案在一个助手卡片内重复显示

- 状态：未修复
- 操作：先问“2+2 等于几？只给答案。”，再问“北京是中国首都吗？只回答是或否。”，从普通完整对话查看记录。
- 实际：`4。` 在同一助手卡片内显示两遍；`是。` 也在同一助手卡片内显示两遍。无凭据多次点击“重试”后，完整记录还会累积多组相同用户行与错误行，进一步增加视觉噪声。
- 预期：同一轮的最终答案只呈现一次；重试历史也应有明确合并或状态区分，避免看似重复故障。
- 影响：用户无法判断是模型重复、消息重复提交还是渲染错误，显著降低可信度。
- 严重度：明显瑕疵
- 置信度：高
- 复现次数：精确答案重复 2/2；无凭据重试累积 1/1
- 截图编号：A23、A24；重试累积辅助证据 A08

### D04 信息不足时擅自检查无关工作目录，并以报告腔过度展开

- 状态：未修复
- 操作：新建无上下文会话，提问“帮我选一个最适合的方案。”
- 实际：在候选方案和选择标准均缺失时，应用先运行 `bash` 检查工作目录，再向用户展示“当前工作目录 pi-home 是空的”等无关内部环境信息；随后用三组编号及多段说明索要信息，而不是先用一两个自然、聚焦的问题澄清。
- 预期：信息不足时应直接、口语化地追问最关键的 1–2 项信息，不应擅自检查无关环境，也不应暴露与任务无关的内部工作目录名。
- 影响：制造越权感和隐私不安，答案也比问题本身更费解。
- 严重度：明显瑕疵
- 置信度：高
- 复现次数：1/1（全新会话）
- 截图编号：A15

### D05 技术简答无视“最多两点”，重复结论且展开过多

- 状态：未修复
- 操作：提问“桌面应用本地保存少量配置，SQLite 和 JSON 哪个更合适？最多两点。”
- 实际：首句能直接给出“推荐 JSON”，但之后先重复结论、列出两点，又追加“什么时候才轮到 SQLite”的三项列表，并再次重复结论和收尾；合计远超两个要点，呈报告腔。
- 预期：第一句给结论，随后最多两个具体、口语化要点，不重复同一结论。
- 影响：简答失去扫读效率，用户明确的长度约束没有被尊重。
- 严重度：明显瑕疵
- 置信度：高
- 复现次数：1/1
- 截图编号：A12（完整回答）、A13（后续闲聊对照）

## 本轮已验证通过

1. **无凭据错误恢复**：提问、连续重试、打开设置再关闭后，小气泡始终只有一个错误块，内容均为中文可执行提示；未见英文引擎原文、`/login`、`/private`、`Contents/Resources` 或 `.md` 路径。设置入口可用。证据 A04–A07。
2. **输入、错误与授权的桌宠连接关系**：从完整桌面前景 UI 估算，输入与错误状态的尾尖到人物首个可见像素约 `9–10 pt`，授权状态约 `9–10 pt`；尾尖相对人物中心水平偏差约 `0–2 pt`，落在门禁目标内。输入区非设计空白约 `12 pt`，错误结果底部余白约 `14 pt`，未见明显空洞。证据 A02、A04、A20。
3. **结果进入详情与连续追问**：结果可打开“当前会话详情”；用户/助手内容、依据与细节、工具轨迹有层级，底部输入可连续追问；点击“收起”后回到桌宠，旧结果不常驻。详情窗口中桌宠未压住输入或按钮。证据 A17–A19。
4. **普通完整窗模型名称**：侧栏/底部显示 `DeepSeek V4 Vision · 实验版`，自然可读，无 `»` 或异常截断；完整模型 id 可通过悬停辅助信息获取。证据 A12、A13。
5. **闲聊简答**：一句话自我介绍直接、口语化，含具体能力说明，无客服式“可以/已完成”。证据 A13。
6. **追问简答**：对“需要我提供哪两样信息”的追问直接回答“候选清单、取舍标准”；详情内继续问也能围绕当前会话作答。证据 A17、A18。
7. **读屏总结**：授权后能正确概括当前“隐私与安全性 > 屏幕与系统音频录制”页面，并控制为两个编号要点。证据 A20、A22、A23。
8. **拒绝隔离与下一问**：拒绝首次读屏前未出现 macOS 系统权限引导；随后提问 `2+2` 得到 `4。`，没有继续执行或续答已拒绝的读屏任务。
9. **停止后的新问题不续答旧任务**：点击“停止生成”后提出首都判断，最终回答针对新问题“是。”，未把新问题继续写成人工智能历史文章。证据 A24。停止是否真正抑制了旧任务本身见覆盖限制。

## 覆盖限制与未裁决项

- **短驻留状态的精确截图测量**：处理中、收到确认、短结果切换很快；无障碍层可观察到状态，但外部完整桌面截图数次在落盘前已退场。没有可靠像素帧的状态不臆测几何通过。
- **约 13 秒自动退场**：单次运行状态时间戳约为 12 秒，接近目标，但 UI 自动化与外部截图存在调度误差；只能作为支持性观察，精确 13 秒及其公差证据不足。
- **详情与自动退场竞态**：成功在短结果驻留期间进入详情 1 次，基本路径可用；未做高频边界压力复现，竞态稳定性证据不足。
- **停止旧任务本体**：已在出现“停止生成”后立即点击，再发送新问题；新问题未续答旧任务。但旧文章仍完整出现在记录中，无法判定是点击前已极速完成，还是停止未生效。因此“停止是否抑制旧任务输出”标为未覆盖，不据此新增缺陷或判通过。
- **A14 信息不足测试**：该问题实际继承了上一轮 JSON/SQLite 上下文，不能作为“无上下文信息不足”证据，已排除；有效证据为新会话 A15。
- **原 A03**：测试夹具作废，严格排除。
