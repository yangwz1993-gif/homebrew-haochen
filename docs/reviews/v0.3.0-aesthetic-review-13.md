## 问题

### P1 — 人物右键入口完全无响应，无法从要求入口打开完整对话

复现：

1. 仅运行指定候选 App 及其 engine，人物可见。
2. 对人物 AX 目标右键；立即查看 CUA 可见截图。
3. 再在人物衣服/中心的可见像素内右键；立即查看截图。
4. 重启同一候选后再次右键并立即截图。

实际：三次均只见人物与点击指示，没有任何上下文菜单；因此无法实际点击要求中的“打开完整对话”。

期望：每次右键都稳定弹出人物菜单，并可由“打开完整对话”到达完整会话。

用户影响：这一入口没有任何反馈，用户会以为 App 未响应；同时阻断了要求中的核心路径。菜单栏的“打开对话”虽可用，但不能替代失效入口。

证据：[动作—结果 A1](./assets/v0.3.0-aesthetic-review-13/action-results.md)

### P1 — `⌘1` 在桌宠前台无任何结果

复现：

1. 重启候选，人物前台可见。
2. 单击人物确保候选取得前台。
3. 按 `⌘1`，立即检查画面。

实际：仍只显示人物，未打开完整会话，也没有反馈。

期望：按产品核心快捷键进入对应会话入口。

用户影响：键盘用户无法通过约定入口进入会话，且“按了没反应”降低可靠感。同一候选、同一输入方式下，`⌘,` 能在人物场景正确打开设置，因此这不是一次泛化的 Command 键失效。

证据：[动作—结果 A3](./assets/v0.3.0-aesthetic-review-13/action-results.md)

### P2 — 小窗简答直接暴露 Markdown 星号

复现：

1. 在小窗输入“推荐一个适合上海秋天的周末散步安排。”
2. 查看简答。
3. 点击“继续提问”，输入“如果下雨呢？”。
4. 查看追问简答，再打开详情。

实际：小窗分别显示 `**武康路—衡山路**` 与 `**上生·新所 → 静安寺**`；星号作为正文字符直接可见。进入详情后，同样文本才被正确渲染为粗体。

期望：简答气泡与详情页一致地渲染或清理 Markdown，不暴露格式控制符。

用户影响：这是高频主界面中的明显视觉瑕疵，会让本来精致的气泡像未完成的调试输出。

证据：[动作—结果 A4](./assets/v0.3.0-aesthetic-review-13/action-results.md)

## 通过项

- `⌘,`：人物、人物小窗、完整会话三个前台场景均打开标题为“haochen 设置”的同一设置页；关闭后均可回到原场景。
- `⌘N`：完整会话中创建新会话，旧主题保留在侧栏。
- 小窗：输入、人格化思考提示、简答、继续提问、和详情入口层级清楚；奶油色卡片、绿色主按钮和气泡尖角形成一致语言。
- 追问：点击“继续提问”后能正确承接上文；详情页有“结论 / 依据与细节”两层信息结构。
- 短答临时退场：结果退场后人物仍可再次唤起干净输入态，完整会话可回看历史。
- 长回答中止：在多个正文小节已经可见且仍显示“停止生成”时点击停止，当前视口保留正文，并以橙色明确标记“已停止生成 · 上述内容未完成”；关闭完整会话再重开后，内容位置与未完成语义均保留。
- 会话标题：连续建立咖啡与耐阴植物两个主题后，左栏标题可明确区分；长回答主题也可与二者区分。
- 最大化/恢复：完整会话通过窗口 zoom 动作最大化并恢复，内容、侧栏和输入区均可用；候选未复现误绑定版本的极窄窗口。
- 设置凭据：有效态和失败态均为 secure text field；仅显示状态与占位文案，没有明文 Key。
- 读屏拒绝：读取前显示“读吧 / 不读”明确同意界面；点击“不读”后未执行读取，完整历史显示“read_screen 未执行 · 未获授权”。
- 无凭据错误：中文错误说明 API Key 无效或格式不正确；Retry 三次分别显示明确计数并保持恢复入口；“检查设置”直达失败状态与 secure 输入框；完整历史保留红色错误卡。
- DMG SHA-256 与给定值一致。

## 未裁决项

- 四边摆放：CUA 可连续拖动人物并重新连接窗口，但其 App 截图是窗口局部坐标，无法可靠证明人物已分别贴到四个全局屏幕边缘。本轮不把这一工具限制误判为产品失败，也不把它记为通过。
