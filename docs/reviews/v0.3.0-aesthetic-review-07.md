2. 详情窗口中，左侧会话栏很窄，长标题明显省略；窗口左下模型名显示成 `deepseek-v4-flash-vision-e»` 一类截断尾巴，第一眼就像布局没收好。
3. 详情页信息层级可理解，结论与正文分块清楚；但 980 × 708 pt 的固定大窗在短对话时空白较多，且侧栏/主区比例不够精致。
4. 长中文回答在详情页能完整换行，未见正文裁切；输入框、发送按钮和滚动位置可用。
5. 屏幕右上角持续出现一条系统“提示”通知，与产品无关，属于验收环境噪声；所有产品判断均以人物和气泡联合区域为准。

- 错误目录首次仍使用有效 Keychain service，实际请求成功，说明错误条件未成立；这段观察全部作废，不纳入裁决。E 仅采用后来以不存在的 `com.haochen.app.qa.round7.invalid-key` 重启后得到的 `E-01` 至 `E-04`。

### A. 读屏拒绝：通过

授权卡出现前没有 App 自身或系统权限引导抢焦点；卡片清楚写明用途及“读吧 / 不读”。点击“不读”后，约 1.0 秒与约 1.7 秒的完整桌面截图中均可见人物与独立气泡，文案为“没读屏……别的窗口内容我无法确认”，随后自然退场。全路径未出现系统权限引导。证据：`A-01-consent-before-choice-full-desktop.png`、`A-02-refusal-about-1s-full-desktop.png`、`A-03-refusal-about-1.7s-full-desktop.png`。

### B. 读屏同意：成功分支一致；失败分支受限

只有明确点击“读吧”后才进入“已允许，正在读取当前屏幕”。本机读屏实际成功，顶层结论准确识别“系统设置 / 录屏与系统录音”，详情工具卡为绿色 `read_screen ✓ 完成`，成功分支前后一致。证据：`B-01-after-consent-reading-full-desktop.png`、`B-02-consent-result-full-desktop.png`、`B-03-tool-cards-full-desktop.png`。

现机权限条件无法制造真实读屏失败，故“权限不足时顶层失败结论与详情失败工具卡一致、不可绿色成功”未覆盖，不能据此判定通过或失败；这是环境限制，不是产品结论。

### C. 停止上下文：通过

提交“详细列出十条提高专注力的方法”后立即按 Esc，气泡明确显示“已停止 / 我停下来了”；随后提问“请读取当前屏幕并告诉我看到什么”并选择“不读”，最终只回答本次读屏请求：“没读到屏……看不到当前窗口内容”，没有继续输出专注力建议。证据：`C-01-immediate-stop-full-desktop.png`、`C-02-final-current-request-only-full-desktop.png`。

### D. 生命周期与详情竞态：覆盖不足

运行日志中多个普通结果从 `PRESENTING` 到 `IDLE` 约为 11.7–12.6 秒，趋势符合约 13 秒退场；但 `D-01` 至 `D-07` 的完整桌面截图因工具调度延迟，文件名时间点不能作为精确的 +2 / +10 / +13 秒 UI 证据。详情打开、Esc 收起和再提问均实际完成，新答案也出现，但跨工具调用耗时使旧计时器已无可靠重叠，因此不能严格证明“旧定时器不会吞掉新请求”。这些截图仅保留审计轨迹，不用于产品缺陷结论。

### E. 错误恢复：恢复链路通过，错误文案有明显瑕疵

在校准后的无凭据环境中，首次错误、重试、进入 App 设置、关闭设置并恢复错误上下文均可完成；重试和返回后始终只有一个错误块。设置页显示“Keychain 中缺少凭据”，与错误状态不矛盾。证据：`E-01-first-error-full-desktop.png` 至 `E-04-closed-settings-restored-error-full-desktop.png`。但错误正文直接暴露英文引擎信息与内部路径，详见问题 1。

## 可复现产品问题（按严重度）

### 1. 错误气泡把内部引擎报错和绝对路径直接交给普通用户

- **证据编号**：`E-01-first-error-full-desktop.png`、`E-02-retry-single-error-full-desktop.png`、`E-04-closed-settings-restored-error-full-desktop.png`
- **状态与操作**：无有效 API Key 的校准错误环境中提出普通问题；再点“重试”；进入设置后关闭。
- **实际**：气泡正文显示英文 `No API key found... Use /login...`，并暴露 `/private/tmp/.../Contents/Resources/engine/docs/providers.md` 与 `models.md`；这些路径和 `/login` 对 GUI 用户不可操作。
- **测量**：错误气泡约 `380 × 255 pt`；三次状态都完整重复同一大段技术文本，底部仅有“检查设置 / 重试”。
- **预期**：用中文说明“当前模型缺少 API Key”，给出一句可执行建议；技术详情应折叠或仅在详情页出现，不能暴露构建内部路径。
- **影响**：普通用户会认为 App 崩坏或仍是开发版，无法从正文判断下一步，明显降低信任。
- **严重度 / 置信度**：明显瑕疵 / 高
- **复现次数**：3/3（首次、重试、关闭设置返回）
- **复验点**：无凭据提问一次，确认小气泡只出现本地化、人话化结论且无 `/private/tmp`、`/login`、`.md` 路径。

### 2. 所有小气泡与人物之间的垂直间距超出门禁基线

- **证据编号**：`BL-02-input-full-desktop.png`、`BL-06-followup-result-full-desktop.png`、`A-01-consent-before-choice-full-desktop.png`、`E-01-first-error-full-desktop.png`
- **状态与操作**：分别观察输入、短结果、授权和错误气泡的完整桌面联合画面。
- **实际**：尾巴方向正确，但气泡整体悬在人物头顶之上，连接感偏弱。
- **测量**：人物约 `96 × 96 pt`；尾巴尖到人物顶部约 `14–17 pt`，高于规定 `6–10 pt`；尾巴尖相对人物中心水平偏差约 `0–2 pt`，水平对齐正常。
- **预期**：垂直间距稳定在 6–10 pt，同时保持尾巴中心偏差不超过 4 pt。
- **影响**：人物和气泡像两个独立悬浮窗，削弱桌宠“在说话”的整体感，普通用户在空旷桌面上会立即注意。
- **严重度 / 置信度**：明显瑕疵 / 高
- **复现次数**：至少 8/8 个小窗状态均保持同类间距
- **复验点**：任取输入态与长授权态各一张完整桌面截图，测量尾巴尖到人物顶部均为 6–10 pt。

### 3. 详情页模型名被截成异常尾巴，侧栏完成度不足

- **证据编号**：`BL-07-details-full-desktop.png`、`BL-08-long-answer-details-full-desktop.png`、`B-03-tool-cards-full-desktop.png`
- **状态与操作**：从任一结果点“查看详情”，观察窗口左下模型状态区。
- **实际**：模型名显示为类似 `deepseek-v4-flash-vision-e»` 的非自然截断；长会话标题也在狭窄侧栏中很早省略。
- **测量**：详情窗约 `980 × 708 pt`，左侧栏约 `255 pt`；完整模型名 `deepseek-v4-flash-vision-exp` 无法显示，末端出现异常箭头/尾字符。
- **预期**：使用规范省略号、可读别名或悬停完整名，不能呈现像乱码或残缺控件的尾巴。
- **影响**：详情页是用户核对工具与模型状态的可信界面，异常截断会被理解为布局破损。
- **严重度 / 置信度**：明显瑕疵 / 高
- **复现次数**：3/3
- **复验点**：展开详情，确认模型名以完整名称或规范省略号显示，末端无 `»` 异常字符。

- 精确 +2 / +10 / +13 秒完整桌面截图和旧定时器重叠竞态未形成可靠证据；`D-01` 至 `D-07` 不用于缺陷裁决。

## 严格结论

**NOT PASS。** 无阻断问题；存在 3 项高置信度“明显瑕疵”，其中错误态直接泄露英文引擎信息与内部绝对路径，且人物—气泡垂直间距系统性超出强制基线。按门禁规则，任一明显瑕疵未清零都不得 PASS。另有 B、D、减少动态效果和多屏的覆盖缺口，本轮也不能据此宣称完全通过。
