## 1. 总结：NOT PASS

视觉方向已经基本成立：桌面上不再常驻一个笨重的大对话框，人物、尾巴气泡、米白底、墨线与绿色主按钮能组成统一的桌面宠物；角色是戴眼镜、穿连帽衫的成年像素工程师，不是卡哇伊幼态。短结论、长回答摘要、停止态和授权卡的主要信息也都能用人话表达。

但当前仍不能交付普通用户。核心阻断是：成功回答已经生成并写入详情后，桌面气泡有时会从“收到，我接住了”直接消失，用户看不到答案，也没有“去详情查看”的落点。该问题在同一有效环境中连续出现在“只回复：好”“用一句话解释云朵”“只回复：测试”三次请求；答案只能从菜单重新打开完整对话后找到。这破坏了最基本的“发问—看到回答”闭环。

此外，读屏拒绝被绿色“✓ 完成”包装，以及错误气泡与设置页对 API Key 状态的相互矛盾，会让权限与故障恢复显得不可信。

6. 较长回答：约 500 字回答在详情页完整显示；从桌面气泡发起长回答时，完成后以一段紧凑结论承接，并提供“继续问 / 查看详情”。
7. 查看详情：完整对话窗口、侧栏、用户气泡、结论卡、正文卡、工具卡、固定底部输入区均实际操作。
8. 继续问：询问“你刚才列了几条？只回答数字”，正确返回“7条”，上下文连续。
9. 停止：发送 2000 字长文请求后立即停止；首帧与稳定态均为“已停止 / 我停下来了。停止前生成的内容已经保留”，并提供“继续问 / 查看已有内容”。

12. 工具详情：展开拒绝后的工具卡，能看到“用户拒绝了读屏请求（或超时未确认）”。
13. 错误恢复：在隔离错误环境中触发“API Key 无效或格式不正确”，点击“检查设置”，关闭设置后原错误卡与“重试”仍在；点击“重试”仍作用于原待处理请求，没有丢失错误上下文。
14. 全流程视觉：人物、输入气泡、处理中气泡、结论气泡、停止气泡、详情窗口和设置窗口均以真实时间顺序观察。

## 3. 分级问题

### 阻断

#### B1. 成功的短回答可能不在桌面气泡出现，完成时气泡直接消失

- 复现：打开过“查看详情”并关闭，点击人物；发送“只回复：好”或“用一句话解释云朵是什么”或“只回复：测试”；看到“收到，我接住了”；约 2 秒后界面直接退回仅有人物的闲置态。通过菜单“haochen → 打开对话”能看到对应答案确实已经生成。
- 肉眼证据：发送时仍有状态气泡：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/08-bubble-sent-feedback.png`；完成后只剩人物：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/09-bubble-result-missing.png`；答案“测试”实际存在详情：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/10-hidden-answer-in-detail.png`。
- 用户影响：普通用户会认为回答失败或被吞掉；他们不会知道答案藏在菜单后的完整对话中。
- 明确改进标准：每一次成功完成都必须从处理气泡原位过渡到可见结果。即使没有单独摘要，也至少展示正文首段或明确的“回答已完成 / 查看回答”卡；结果必须保持到用户点击继续、查看详情、关闭或超时达到一个足够阅读的时长。回归测试中连续 50 次短答不得出现“成功写入详情但桌面无任何完成态”。

### 重要

#### I1. 第一次出现的“怎么开始”提示过快消失

- 复现：以给定有效隔离目录首次启动；可访问树一度出现“点一下我，随时开聊”，紧接着的首次截图已经只剩人物，没有文字、按钮或可见点击暗示。
- 肉眼证据：提示消失后的首次闲置画面：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/01-character-idle.png`；用户猜到点击后才出现输入：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/02-compact-input-bubble.png`。
- 用户影响：熟悉桌面宠物的人可能会点人物；普通用户在 10 秒内未必知道它可点击，更不知道点击后能输入。
- 明确改进标准：首次出现时将“点我开始”保持至少 6–10 秒，或直到第一次点击；人物应有持续但克制的可点击反馈（例如悬停、轻微呼吸/目光、辅助功能名称“点击开始对话”）。首次用户无需试错即可在 10 秒内进入输入态。

#### I2. 拒绝读屏仍被折叠工具卡标为绿色“✓ 完成”

- 复现：请求读取当前屏幕；在“haochen 想读屏”卡点击“不读”；首帧下方写“已拒绝读屏”，但工具卡标题仍是绿色“✓ 完成”；最终折叠后只剩“read_screen ✓ 完成”，拒绝语义完全退到详情里。
- 肉眼证据：拒绝首帧：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/04-read-screen-denied-first-frame.png`；拒绝后的最终折叠态：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/05-read-screen-denied-final.png`；授权卡本身：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/03-read-screen-consent.png`。
- 用户影响：绿色对勾通常表示工具成功执行，与用户明确拒绝相冲突；在隐私敏感动作上会直接损害信任。
- 明确改进标准：拒绝、超时、成功必须是三个一眼可分的顶层状态。拒绝使用中性/灰色或琥珀色“未执行 · 已拒绝”，不得出现绿色对勾；折叠状态也必须保留“已拒绝”，不要求用户展开验证。

#### I3. 错误气泡说 Key 无效，设置页却用绿色显示“已安全存储”

- 复现：在给定错误环境发送任意请求；错误卡提示“API Key 无效或格式不正确”；点击“检查设置”；API Key 卡却显示绿色“deepseek 已安全存储在 Keychain”，输入框占位也写“已安全存储，输入新 Key 可替换”。
- 肉眼证据：错误与重试：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/07-error-retry-context.png`；从该错误进入的设置页：`/Users/yangwz/Documents/workspace/haochen/docs/reviews/assets/v0.3.0-aesthetic-review-04/06-error-settings-contradiction.png`。
- 用户影响：用户被引导来“检查”，但最醒目的绿色信息告诉他配置正常，无法判断应重新输入、重新验证还是换模型。“已存储”只描述存放位置，不代表当前可用。
- 明确改进标准：设置页同时、明确区分“凭据存在”和“最近验证状态”。从错误卡进入时应突出“当前凭据验证失败/格式错误”，主动作改为“重新输入并验证”或“重新验证”；绿色成功态只在本次验证确实通过后出现。关闭设置后保留原错误和重试这一点应继续保持。

## 4. “旧式常驻大框是否已经消失”裁决

**明确裁决：桌面主路径中的旧式常驻大框已经消失。**

闲置态只有人物；点击后出现贴着人物、带尾巴的紧凑输入气泡；处理中、停止和结论态都按内容适度增高，没有铺满桌面，也没有出现明显遮挡、裁切或突兀的大幅尺寸跳变。长回答在桌面层只给紧凑结论，完整内容由用户主动点击“查看详情”后进入标准窗口。这是合理的层级切换，不能算“常驻大框复发”。

正面证据：输入气泡 `02-compact-input-bubble.png`；停止态 `11-stop-first-frame.png`；长回答紧凑结论 `12-long-answer-compact-summary.png`，均位于上述 assets 目录。

完整对话窗口本身仍有明显“固定大画布 + 短内容大留白”，属于详情页润色问题，不推翻“桌面常驻大框已消失”的结论。

## 5. 视觉与文案裁决

- 人物：PASS。成年像素工程师气质明确；黑发、橙色眼镜/面部、深色连帽衫成熟克制，不是幼态吉祥物。
- Retina：PASS。人物采用有意的硬边像素语言，边缘没有明显双线性糊边；文字、描边和按钮在 2940 × 1912 原生截图中清楚。
- 气泡与人物：PASS。气泡尾巴稳定指向人物，米白/墨线/绿色与人物配色一致，像同一个产品而不是悬浮表单叠在角色上。
- 按钮层级：PASS。发送、查看详情、读吧为绿色主动作；继续问、不读为次动作；停止为红色危险动作，扫一眼能区分。
- 文案：大体 PASS。“收到，我接住了”“我停下来了”“需要读取…点读吧允许；点不读拒绝”都说人话；主要例外是拒绝仍显示“✓ 完成”和错误/设置状态矛盾。
- 遮挡与裁切：桌面气泡未见正文或按钮裁切；详情侧栏存在文本截断，长回答需滚动但没有正文重叠。

## 6. 可交付门槛

当前门槛：**不得发布给普通用户。**

转为 PASS 至少需要：

1. 修复 B1，任何成功回答都必须在桌面层留下可见、可操作的完成态；完成 50 次短答与 20 次“打开详情→关闭→继续问”回归，不得吞结果。
2. 读屏拒绝/超时不得再显示绿色“✓ 完成”；同意、拒绝、超时、工具失败四种状态分别做首帧和折叠态验收。
3. API Key 错误进入设置后必须看到与错误一致的失败状态及明确修复动作；用无 Key、格式错误、鉴权失败、有效 Key 四条真实路径验收。
4. 首次提示应在 10 秒内稳定告诉普通用户“点击人物开始”，并具备辅助功能名称。
5. 保持本轮已经通过的桌面紧凑气泡、停止态、长回答摘要、上下文继续问、成年角色和按钮层级，不得为修复而退回常驻大框。

满足以上 1–4 且没有新增阻断后，P1/P2 可以作为不阻塞 v0.3.0 的后续润色；在此之前结论保持 **NOT PASS**。
