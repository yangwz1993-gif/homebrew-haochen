## 结论

不通过。真实问答已可用，输入、整理、短/长结果均能到达，人物和气泡的几何关系稳定；
但发送回执不可辨认、拒绝权限后短暂显示相反语义、停止结果自相矛盾，均不满足交付门禁。

## 问题

### A01 首次启动仍难以发现如何交互

- 状态与操作：从全新隔离目录首次启动，观察并寻找入口。
- 实际：只显示 `96 × 96` 人物，没有常显点击提示、状态或可见反馈。
- 测量：前 `10s` 内只能靠猜测点击人物。
- 预期：第一次使用就能识别“点击人物开始”。
- 影响：核心能力的发现成本过高。
- 严重度 / 置信度：明显瑕疵 / 高。
- 复验点：从全新隔离目录启动，不悬停人物，观察是否出现一次性轻提示。

### A02 `ACKNOWLEDGING` 快到肉眼不可辨认

- 状态与操作：输入短问题并发送，以约 `50–100ms` 间隔观察和连拍。
- 实际：输入框直接进入“正在组织回答”；普通观察约 `600–983ms` 时已经是
  `COMPOSING`，未辨认到“收到”回执。
- 预期：发送成功后出现短促但可识别的即时回执，再进入工作状态。
- 影响：用户无法建立“点击已生效”的确定感，网络慢时容易重复提交。
- 严重度 / 置信度：明显瑕疵 / 高。
- 复验点：逐帧核对发送后的第一条状态，回执应稳定可见且不过度拖慢请求。

### A03 拒绝读屏后仍短暂显示正在读取

- 状态与操作：请求读屏 → 点击“不读” → 持续观察 `923ms`。
- 实际：按钮消失后仍显示“正在读取屏幕”和“你允许的屏幕内容”，随后才变为拒绝结果。
- 预期：拒绝后的首帧立即停止所有“正在读取 / 已允许”语义，明确说“好，不读取屏幕”。
- 影响：界面看起来违背了用户的权限选择，直接伤害隐私信任。
- 严重度 / 置信度：阻断 / 高。
- 复验点：拒绝后的首帧和 `500ms` 帧均不得出现读取中或已允许文案。

### A04 停止后仍宣称任务完整完成

- 状态与操作：请求生成千字故事 → 点击停止。
- 实际：约 `829ms` 后同时出现“已停止”和“写好了……完整故事见下方”。
- 预期：只说明“已停下，停止前内容已保留”，不得渲染模型在终止竞争中返回的完成式简答。
- 影响：用户无法判断停止是否真正生效。
- 严重度 / 置信度：阻断 / 高。
- 复验点：在慢响应任务中停止，所有可见文案都必须表达未完整完成。

### A05 详情页仍有明显未完成感

- 状态与操作：完成两轮问答 → 点击查看详情。
- 实际：侧栏出现“结论 结论”，模型名在窄栏生硬断行；消息集中上部，主区存在大片空白。
- 预期：标题唯一、模型信息可读、空状态和已有内容的版面密度平衡。
- 影响：从精致小窗展开后，产品完成度明显下降。
- 严重度 / 置信度：明显瑕疵 / 高。
- 复验点：两轮短对话后展开详情，检查标题、侧栏底部和主内容区。

## 实测矩阵与几何

- `LISTENING` 空输入与两行输入：`400 × 153`；人物 `96 × 96`；垂直间距 `8px`；
  尾巴水平偏差约 `0px`；最大连续空白分别约 `51px / 33%`、`27px / 18%`。
- `PRESENTING`：短回答约 `400 × 143`，长中文约 `400 × 224`；垂直间距约
  `8–12px`，尾巴偏差约 `0px`；长回答最大连续空白约 `44px / 20%`。
- `PERCEIVING`：约 `400 × 294`，尾巴居中，人物切到思考姿态。
- 状态切换没有水平跳位，主要变化为气泡向上增高。

实际可达：`LISTENING` 空/两行、`PERCEIVING`、`COMPOSING`、`PRESENTING` 短/长、
`CANCELLED`。实际失败：`ACKNOWLEDGING` 不可辨认、拒绝权限反馈、停止语义。
未覆盖：稳定 `ACTING`、隔离 `ERROR` 的设置往返与重试。

仓库 `evidence-*.png` 与 `visual-metrics.json` 只作为 mock 补证，不视为真实包通过；本轮
还发现旧补证中的 `evidence-acting` 实际已进入 `PERCEIVING`，`evidence-error` 的状态枚举
仍显示 `LISTENING`，验收工具必须继续修正，不能靠文件名宣称覆盖。
