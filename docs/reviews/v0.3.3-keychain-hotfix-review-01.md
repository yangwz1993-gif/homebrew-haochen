# v0.3.3 Keychain hotfix 独立用户验收 01

## 裁决

**NOT PASS · 待修复后复验。**

候选包已经解决本轮最危险的问题：模拟 v0.3.2 已完成首启的用户升级后，haochen 没有再唤起 macOS `SecurityAgent` 钥匙串密码框，而是直接把用户带到应用内的“连接模型”页。无效测试 Key 的失败路径、从短气泡进入设置、短气泡关闭按钮也都可用。

但当前升级页只说“尚未验证”，没有告诉用户“这是版本安全身份升级导致的一次性重填”，也没有说明旧 Key 没有被读取、覆盖或删除。一个刚被系统钥匙串弹窗吓到的普通用户会理解成自己的 Key 突然失效，仍需要猜发生了什么。按本轮明确要求的“应用内清晰引导重新填写 API Key”，这属于阻断交付的用户体验缺口。

此外，自定义 OpenAI 兼容模型升级场景必须保留原 API URL、模型 ID 和显示名称，只让用户重新填写 Key。本候选尚未提供该升级态的完整黑盒证据，本轮不得放行。

## 阻断项

### P1-01：升级页没有解释为何必须重填 Key

复现：使用“首启已完成、旧配置仍在、新 Keychain service 无凭据”的升级状态启动候选。

实际：页面显示“连接模型”和“尚未验证”。

用户感受：像凭据无故丢失或模型坏了；不知道这与 v0.3.2 的签名/钥匙串授权问题有关，也不知道旧 Key 是否还安全。

放行要求：在输入框上方加入一段简短、直白、只针对升级用户的说明，至少说清：

1. haochen 的应用安全身份已升级；
2. 为避免再弹出系统钥匙串授权框，需要在应用内重新填写一次 API Key；
3. 旧 Key 不会被读取、覆盖或删除；验证成功后新 Key 才会安全保存；
4. 文案不要出现 ACL、designated requirement、cdhash 等开发术语。

建议文案基线：`haochen 的应用安全身份已升级。为避免再次弹出系统钥匙串密码框，请在这里重新填写一次 API Key。旧 Key 不会被读取或删除；验证成功后，新 Key 才会安全保存。`

### P1-02：自定义模型升级必须只补 Key，不能让用户重配整套模型

放行要求：对原来使用自定义 OpenAI 兼容模型的升级用户，进入模型页时自动选中“自定义”，完整保留并展示原 API URL、模型 ID 和显示名称；Key 保持空白并明确要求重新填写。验证失败不得覆盖这些原配置，验证成功后才更新 Keychain。

## 非阻断建议

- “Keychain 中缺少凭据”对普通用户偏技术化。升级态更适合显示“需要重新填写 API Key”，并把原因放在紧邻输入框的位置。
- 设置页仍使用较粗的多层描边，信息密度尚可，但视觉重量略重；本 hotfix 不必扩大范围，可放入后续统一视觉精修。
- 无效 Key 后输入值仍留在密码框，方便用户修正，这是合理的；建议在离开页面或关闭窗口时清空，避免下次回到页面仍保留测试值造成不安。
