## 明显瑕疵

### 1. 完整会话里的 `⌘↩` 会误发送，和提示及桌宠气泡行为相反

完整会话输入框明确提示“↩ 发送，⌘↩ 换行”。实际输入“第一行”后按 `⌘↩`，消息立刻发出、输入框清空；在桌宠气泡中，同一快捷键却会正常插入换行。用户准备多行内容时会被意外发送，而且同一 App 的两个入口规则不一致。

证据：[phase-a-02-command-return-sent.png](assets/v0.3.0-aesthetic-review-10/phase-a-02-command-return-sent.png)

### 2. 多行用户输入进入历史后丢失换行

输入态正确显示三行文本，发送后右侧用户气泡把所有换行压成空格和连续段落。清单、步骤、代码或逐行改写请求都会失去原始结构。

证据：[phase-a-03-multiline-collapsed.png](assets/v0.3.0-aesthetic-review-10/phase-a-03-multiline-collapsed.png)

### 3. 没有“结论”分段时，桌宠结果会直接消失

请求“只回复‘好’”时，先出现正常的“收到，我接住了”处理中气泡，完成后气泡直接消失，只剩桌宠，没有最终可见答案、详情入口或错误。打开完整会话才发现“好”被放进“依据与细节”，而“结论”卡片完全缺失。模型输出格式稍有偏离时，核心的紧凑结果入口不能安全降级，普通用户会以为请求凭空消失。

证据：[phase-b-10-empty-summary-disappears.png](assets/v0.3.0-aesthetic-review-10/phase-b-10-empty-summary-disappears.png)

### 4. 桌宠可被拖入 Dock 区域，底部大面积遮挡

把人物拖到屏幕底边后，气泡尾尖仍指向人物头部，但人物身体乃至脸部会被 Dock 覆盖，结果/处理中同样受影响。应用没有按 macOS 可用工作区约束桌宠位置；这不是人物素材问题，而是边缘放置交互与系统 UI 的直接冲突。

证据：[phase-b-08-bottom-edge-input.png](assets/v0.3.0-aesthetic-review-10/phase-b-08-bottom-edge-input.png)、[phase-b-09-bottom-edge-processing.png](assets/v0.3.0-aesthetic-review-10/phase-b-09-bottom-edge-processing.png)

## 轻微建议

### 1. 长会话标题截断不自然

长标题在左栏显示为“请帮我解释为什么天空在晴朗白:”，末尾是突兀的冒号，没有省略号，也不像完整句子。不同短标题可以区分，但长标题精致度不足。

证据：[phase-b-11-three-sessions-long-title.png](assets/v0.3.0-aesthetic-review-10/phase-b-11-three-sessions-long-title.png)

### 2. 少量消息时完整会话过于空旷

普通窗口和最大化都能保持稳定阅读列，长答案宽度也可读；但少量消息时，左栏、最右侧用户气泡、底部输入框彼此分散，中间大片空白，让界面更像未完成画布而不是正在工作的对话。

证据：[phase-a-01-chat-window-new-session.png](assets/v0.3.0-aesthetic-review-10/phase-a-01-chat-window-new-session.png)、[phase-b-12-maximized-chat.png](assets/v0.3.0-aesthetic-review-10/phase-b-12-maximized-chat.png)

### 3. 明确拒绝后状态文案把“拒绝”和“超时”混在一起

用户明确点击“不读”后，最终工具标签显示“已拒绝/超时”。后续回答能正确说明没有读到屏幕，但状态文案没有精确反映刚发生的动作，略削弱权限反馈的可信度。

证据：[phase-b-16-read-screen-refused.png](assets/v0.3.0-aesthetic-review-10/phase-b-16-read-screen-refused.png)

## 核心体验与明确约束

- 桌宠提交后不会常驻大对话框；首先显示“收到，我接住了”，然后切换为紧凑结论和“继续问 / 查看详情”。正常结构化回答时，这条路径自然、清楚。
- 详情窗口把“结论”和“依据与细节”分卡显示，`Esc` 可收起；再次点击桌宠能回到输入态，没有死路。证据：[phase-b-01-online-result.png](assets/v0.3.0-aesthetic-review-10/phase-b-01-online-result.png)、[phase-b-02-detail-window.png](assets/v0.3.0-aesthetic-review-10/phase-b-02-detail-window.png)
- “2+2 等于几？只给答案”的最终可见内容严格为 `4`，没有前后缀。证据：[phase-b-03-exact-short-answer.png](assets/v0.3.0-aesthetic-review-10/phase-b-03-exact-short-answer.png)
- “用一句不超过三十字总结：太阳能的主要优点”的最终可见结论为“太阳能清洁可再生、取之不尽，不产生污染排放。”，按 Unicode 可见字符计 22 个，满足不超过 30 字。证据：[phase-b-04-thirty-char-summary.png](assets/v0.3.0-aesthetic-review-10/phase-b-04-thirty-char-summary.png)
- “最多两点”的 Python 性能建议最终确实只有两条主体建议，且表达可执行。证据：[phase-b-14-two-point-tech-advice.png](assets/v0.3.0-aesthetic-review-10/phase-b-14-two-point-tech-advice.png)

## 稳定性与人话

- 含糊请求“帮我处理一下这个”没有擅自读目录或调用工具，而是先追问对象和目标，行为稳妥。证据：[phase-b-13-ambiguous-request-clarifies.png](assets/v0.3.0-aesthetic-review-10/phase-b-13-ambiguous-request-clarifies.png)
- 4 条计时样本的首个可见反馈为 1.366–1.916 秒；最终结论为 6.646–7.492 秒。等待期间均有明确处理中状态，没有静默卡死。
- 正常回答的结论总体紧凑、语气自然；详情能承载较长解释，不把全部内容挤进桌宠小窗。

## 桌宠、气泡与四边缘

- 左、右、上、下四个屏幕边缘均实际拖动验证了输入态；右侧结果态和下侧处理中状态也做了同帧观察。
- 左、右、上边缘时，气泡会自动换边，尾尖指向人物中心或头部，没有明显裁切、跳变；人物发型、眼镜、服装和肤色保持一致。证据：[phase-b-05-left-edge-input.png](assets/v0.3.0-aesthetic-review-10/phase-b-05-left-edge-input.png)、[phase-b-06-right-edge-input.png](assets/v0.3.0-aesthetic-review-10/phase-b-06-right-edge-input.png)、[phase-b-07-top-edge-input.png](assets/v0.3.0-aesthetic-review-10/phase-b-07-top-edge-input.png)
- 下边缘尾尖位置正确，但人物被 Dock 大面积遮挡，见明显瑕疵 4。

## 完整会话与会话管理

- 连续创建超过 3 个会话并分别发送不同首问；短标题能区分，选中态用绿色竖线表示，普通窗口与最大化的消息宽度、输入区和滚动均能使用。
- 最大化后阅读列保持合理最大宽度，没有被拉成整屏长行；桌宠没有浮在会话窗口上遮挡正文。
- 长标题本身能区分，但截断表现不自然；是否能 hover 查看全文因 CUA 不支持 hover，属于证据不足，不臆测通过。

## 权限

- 读屏请求先展示用途说明和“不读 / 读吧”按钮；拒绝前工具停在“运行中”并等待确认，没有出现任何屏幕内容。
- 点击“不读”后工具显示未执行，最终回答明确说明无法看到实时屏幕，确认拒绝前没有发送屏幕内容。证据：[phase-b-15-read-screen-confirm-before.png](assets/v0.3.0-aesthetic-review-10/phase-b-15-read-screen-confirm-before.png)、[phase-b-16-read-screen-refused.png](assets/v0.3.0-aesthetic-review-10/phase-b-16-read-screen-refused.png)

## 错误态与重试

- 无凭据时中文错误为“API Key 无效或格式不正确。请打开设置重新配置后再试。”，含义清楚，没有泄露内部路径、session-dir 或实现细节。证据：[phase-b-17-error-initial.png](assets/v0.3.0-aesthetic-review-10/phase-b-17-error-initial.png)
- 连续点击重试 3 次后，失败结论依次刷新为“刚刚完成第 1/2/3 次重试，仍未连接成功”；计数正确，按钮每次仍可用，没有重复错误卡或布局跳变。因为失败在 CUA 捕捉延迟内完成，无法单独证明极短暂的“正在重试（第 N 次）”中间帧；最终等价计数反馈已逐次核验。证据：[phase-b-18-retry-1.png](assets/v0.3.0-aesthetic-review-10/phase-b-18-retry-1.png)、[phase-b-19-retry-2.png](assets/v0.3.0-aesthetic-review-10/phase-b-19-retry-2.png)、[phase-b-20-retry-3.png](assets/v0.3.0-aesthetic-review-10/phase-b-20-retry-3.png)

## 发布建议

在下一轮门禁前，至少修复并真机回归以下四项：

1. 统一完整会话与桌宠气泡的 Enter / `⌘Enter` 语义，并让提示与真实行为一致。
2. 保留用户消息原始换行。
3. 当结构化响应缺少“结论”时，用正文或“依据与细节”生成可靠的可见回退结果，不能自动消失。
4. 拖动桌宠时按 macOS visible frame / Dock / 菜单栏约束最终位置。

以上四项未修复前，本轮裁决保持 **NOT PASS**。
