## 原始观察

### 阻断

- 未观察到阻断。启动、引擎响应、输入发送、详情打开和收起均可继续完成。

### 明显瑕疵

1. **停止生成后，截断回答被包装成普通完成卡片，没有任何“已停止 / 未完成”状态。**
   - 操作：在详情页要求生成十节长文；出现“停止生成”后点击停止。
   - 实际：处理中状态消失，输入框与普通“发送”按钮立即恢复；截断内容留在常规回答卡片中。末句肉眼可见停在“不确定度乘积有一个下限 Δ”，既没有句号后的完整表达，也没有停止标识、淡出样式或继续生成入口。
   - 普通用户感受：很容易把截断内容误认为模型已经完整回答；尤其滚动到中段时，界面没有任何可辨识的中止语义。
   - 证据：[08-stop-incomplete.jpg](./08-stop-incomplete.jpg)

### 轻微建议 / 可发现性疑点

1. **会话管理入口在桌宠气泡与“当前会话详情”窗口中都不可见。**
   - 自由探索看到的详情页顶栏只有“当前会话详情”和“收起 Esc”，正文区也没有新建会话、历史会话、会话切换或清空入口。
   - 尝试双击/右键桌宠、常见 `⌘N` 与 `⌘,` 均没有出现会话管理 UI。
   - 这不等同于证明产品完全没有会话管理；但从首次普通用户角度，其入口至少高度不可发现。若入口依赖菜单栏常驻项，建议在详情页提供显式入口或引导。
   - 证据：[03-detail-overview.jpg](./03-detail-overview.jpg)

2. **人物肤色偏高饱和橙色，眼镜/悬停蓝光会进一步把脸部推向橙蓝强对比。**
   - 成年像素工程师身份、发型、眼镜和卫衣总体成立，没有幼态化，也没有与输入气泡重叠冲突。
   - 但肤色的橙色饱和度略像材质色而非肤色；建议只做小幅降饱和/提亮验证，不建议重做人设。
   - 证据：[09-character-bottom-edge.jpg](./09-character-bottom-edge.jpg)

### 表现自然且可交付的已观察项

1. **处理中反馈简洁、动作明确。** “收到，我接住了”配合“停止”与宠物高亮，短促且不像系统日志。
   - 证据：[01-vague-processing.jpg](./01-vague-processing.jpg)

2. **含糊问题会主动澄清，回答像人话。** 对“帮我看看这个”没有硬猜，直接问“这个”指哪个窗口/文件/内容，长度与气泡尺寸匹配。
   - 证据：[02-vague-answer.jpg](./02-vague-answer.jpg)

3. **完整会话视觉层次清楚。** 用户气泡靠右，回答拆为“结论 / 依据与细节”，暖底色、绿色标签、圆角与描边统一；中文行宽舒适。
   - 证据：[03-detail-overview.jpg](./03-detail-overview.jpg)

4. **键盘多行规则可用。** 真实键盘序列 `Line one` → `⌘↩` → `Line two` 得到两行；随后 `↩` 正常发送。
   - 证据：[04-multiline-keyboard.jpg](./04-multiline-keyboard.jpg)

5. **四边缘气泡自适应有效。** 左缘时箭头移动到左下，顶部时箭头翻到上侧；输入框与发送按钮都完整可点击，没有出屏或被桌宠遮挡。
   - 证据：[05-left-edge-bubble.jpg](./05-left-edge-bubble.jpg)、[06-top-edge-bubble.jpg](./06-top-edge-bubble.jpg)

6. **详情窗口放大与恢复稳定。** 放大后正文保持居中窄列，没有把每行拉到全屏；恢复后尺寸、滚动与输入区仍正常。
   - 证据：[07-maximized-detail.jpg](./07-maximized-detail.jpg)

7. **连续追问保留上下文。** 含糊问题之后发送两行英文，回答能识别这是“两行普通文本”并反问用户想做检查、改写还是拼接，语气自然，没有无关发散。

- 截图左上角偶发紫色系统屏幕控制指示条不属于产品。
- 收起详情时单帧捕获到灰色过渡窗，下一次即时观察已完成收起，按系统/窗口动画帧排除。
