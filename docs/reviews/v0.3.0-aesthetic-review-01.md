# v0.3.0 独立审美用户验收 · 第 1 轮

- 对象：`0.3.0-dev.1`，提交 `12db9b8`
- 方式：独立角色实际启动开发包；首次审视前未阅读代码、PR、设计理由和开发规划
- 结论：**不通过**。存在影响基本信任和操作预期的明显瑕疵，需要修复后复验。

## 阻断与明显瑕疵

1. 失败后“正在组织回答 / 停止”与错误卡同时存在，用户无法判断是否仍在处理。失败时应立即结束工作态，只保留人话错误、重试和设置入口。
2. “继续问”在实测中表现为收起气泡，没有原位恢复输入和聚焦。按钮承诺与反馈不一致。
3. 实测时气泡出现后人物不可见，尾巴指向空处，失去“桌宠正在说话”的漫画关系。
4. 核心入口依赖无提示的双击，单击没有反馈，首次发现性差。
5. 人物在 96px 下像被底边硬切的头像，缺少全身桌宠的落地感和状态表达。
6. 输入、等待、完成态之间高度跳变明显，锚点和内容骨架不稳定。
7. 完成态下半部空白过大，尾巴与内容脱节，容器没有紧贴内容。
8. API Key 错误直接暴露英文技术详情和示例字符串，应转换为简短用户文案，技术详情折叠。

## 精修项

1. 粗描边、大圆角、小尾巴、emoji 标题和 macOS 控件语言混杂，尚未形成统一视觉体系。
2. 中文长文本行距和层级不足，标题、状态、正文与操作的阅读节奏偏平。
3. 继续问、查看详情、发送、关闭、重试的图标、尺寸、圆角与主次规则不统一。
4. 完整对话窗空状态、侧栏、模型信息和输入区仍有明显原型感。

## 已实际体验

- 开发包启动与桌宠第一印象；
- 单击、双击和气泡唤起；
- 初始输入、无效凭据错误、模拟成功回答；
- 短答与较长中文摘要、结果操作；
- “继续问”和菜单打开完整对话窗口。

## 本轮未验证

有效真实凭据下的流式节奏、工具与权限卡、超长内容、图片、多轮历史、多屏边缘、
拖动、完整连续动画和真实读屏。它们必须在后续有对应条件时补验，不能视作已通过。

## 复验条件

上述 8 个明显瑕疵完成修复并产出新的隔离开发包后，再由未参与实现的独立审美用户
实际复验。开发者自测不能关闭这些问题。
