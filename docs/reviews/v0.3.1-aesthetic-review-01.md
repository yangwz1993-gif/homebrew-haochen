## 问题清单

### P1 — 输入编辑区无法容纳常见长句或两行文本

复现：打开气泡，输入 `请用一句人话解释什么是 Homebrew，并说出一个用途。`；或输入 `line1`，按 Command+Return，再输入 `line2`。

实际结果：

- 稍长中文自动换行后，第二行被底部裁掉，字符、光标与下划线挤在一起；
- 两行输入时第一行被顶部裁掉，只残留字符下沿；
- 编辑区右侧出现突兀的纵向滚动条，但可视高度又不足以让用户辨认两行内容；
- 输入框本身没有越过气泡实体，但这是以固定压扁编辑区换来的，核心编辑可用性仍然失败。

影响：这是应用最高频的主入口。用户不能在发送前确认完整问题，属于阻断交付的核心体验缺陷。

证据：

- 多行：[整屏](assets/v0.3.1-aesthetic-review-01/03-valid-multiline-full.jpg) / [紧裁](assets/v0.3.1-aesthetic-review-01/04-valid-multiline-tight.jpg)
- 长句：[整屏](assets/v0.3.1-aesthetic-review-01/05-valid-long-input-full.jpg) / [紧裁](assets/v0.3.1-aesthetic-review-01/06-valid-long-input-tight.jpg)

验收要求：编辑区至少平滑容纳 2–3 行，随内容增长但设合理上限；增长后仍必须完全位于气泡实体内，滚动条仅在超过上限时出现。Command+Return 产生的新行必须立即完整可见。

### P2 — 首次打开的“欢迎语 + 输入”气泡有大块无意义空白

首次启动后点击人物，欢迎语卡片和输入区之间留下接近一整行卡片高度的空白。气泡因此明显变高、变重，像一个尚未布局完成的面板，违背“像人物说话、轻量不挡桌面”的目标。

证据：[整屏](assets/v0.3.1-aesthetic-review-01/01-valid-fresh-greeting-input-full.jpg) / [紧裁](assets/v0.3.1-aesthetic-review-01/02-valid-fresh-greeting-input-tight.jpg)

验收要求：欢迎语、输入区之间只保留稳定的小间距；首次态总高度应由真实内容决定，不能出现无法解释的空白区。

### P2 — 人物不是完整全身形象，底部呈明显平切

实际桌面中人物只显示头部和上半身，胸口下方是一条水平切边，手臂、手和下半身均不存在。这不是“完整全身”，也让人物更像贴在桌面的头像挂件，而不是能行动的桌面宠物。

证据：[整屏](assets/v0.3.1-aesthetic-review-01/19-valid-avatar-full.jpg) / [紧裁](assets/v0.3.1-aesthetic-review-01/20-valid-avatar-tight.jpg)

验收要求：在不牺牲既定成年像素工程师风格和当前肤色一致性的前提下，桌面实际渲染必须呈现完整身体轮廓，不能用窗口或素材边界平切。

## 已通过项目

- 短空输入态下，输入区已完全收在气泡实体内，没有压入尾巴或越过外描边；外壳加单条输入下划线不再形成双层圆角输入框。
- 发送按钮比例、文字和视觉权重基本合适；键盘说明移到无障碍描述后，画面明显更安静。
- 左下、右下、左上、右上和顶部翻转均实际拖动核验；气泡未出屏，尾巴能追随人物，翻转方向正确。证据见 `13`–`18` 系列整屏与紧裁图。
- Return 可发送；Command+Return 的功能语义确实产生换行；Esc 可收起输入、停止处理中状态和收起详情。
- 真实问答主链路可完成：发送后状态简洁，Homebrew 简答说人话且结论清晰，详情能展开并包含“结论 / 依据与细节”。证据：[发送状态](assets/v0.3.1-aesthetic-review-01/07-valid-sent-status-full.jpg)、[简答](assets/v0.3.1-aesthetic-review-01/09-valid-summary-full.jpg)、[详情](assets/v0.3.1-aesthetic-review-01/11-valid-detail-full.jpg)。
- 简答在约 15 秒后自动退场；处理中的 Esc 没有随后重新弹回结果。
