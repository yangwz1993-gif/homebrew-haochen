## P0-P3

### P0

### P1-1：全新安装没有展示未完成的首启称呼/模型引导

复现：

1. 确认系统中没有任何 `haochen` / `haochen-engine` 实例。
2. 只读挂载上述唯一 DMG，以全新 Home、全新 Keychain service 直接启动 DMG 内 App。
3. App 只显示宠物；点击宠物直接进入普通短气泡，没有任何首启称呼页或模型配置页。
4. 输入“你好，请用一句话介绍你自己。”并发送。
5. UI 直接报“API Key 无效或格式不正确。请打开设置重新配置后再试”。与此同时，隔离运行状态仍是 `{"version":2,"page":0,"completed":false}`。

影响：真正的新用户既没有看到“haochen 是宠物名且无中文名”的首启说明，也没有机会确认它如何称呼自己或完成模型配置；首个正常动作直接落入凭据错误。这不是旧数据污染：启动前不存在其他实例，Home 和 Keychain service 都是新的。联合证据：[02-input-icons-default.jpg](assets/v0.3.2-aesthetic-review-01/02-input-icons-default.jpg)、[03-first-run-skips-onboarding-key-error.jpg](assets/v0.3.2-aesthetic-review-01/03-first-run-skips-onboarding-key-error.jpg)、[black-box-runtime-proof.txt](assets/v0.3.2-aesthetic-review-01/black-box-runtime-proof.txt)。

补充观察：设置页后续确实清楚写明“桌宠的名字固定是 haochen；这里只设置它如何称呼你”，且隔离目录中没有自动注入“阿晨”。手动输入“阿晨”并点击“保存称呼”后它才成为用户称呼，清空后 UI 明确反馈将自然称“你”。因此问题不是概念文案缺失，而是首启必经页根本没有出现。[05-name-explicit-save.jpg](assets/v0.3.2-aesthetic-review-01/05-name-explicit-save.jpg)

### P1-2：自定义模型 API Key 无法通过 UI 保存，10 秒超时后回滚

复现：

1. 打开设置并展开“自定义模型”。
2. 输入 `http://127.0.0.1:18765/v1`、模型 ID `qa-local`、显示名 `QA Local Timer` 和非敏感测试 Key。
3. 点击“测试并保存”。
4. UI 等待约 10 秒后显示：`保存失败：Command '['/usr/bin/security', 'add-generic-password', ... '-w']' timed out after 10 seconds；已恢复原配置`。
5. 对同一隔离 service/account，以系统 `security add-generic-password -U` 写入同一测试 Key，仅耗时 `0.02 s` 且成功；因此不能归因于 Keychain 不可用。

影响：首启用户无法完成自定义模型配置，且错误把底层命令直接暴露在界面中。回滚有效，未污染原配置，但主功能仍不可用。证据：[06-custom-model-keychain-timeout-rollback.jpg](assets/v0.3.2-aesthetic-review-01/06-custom-model-keychain-timeout-rollback.jpg)、[black-box-runtime-proof.txt](assets/v0.3.2-aesthetic-review-01/black-box-runtime-proof.txt)。

## 环境问题与覆盖限制

- 本机网络代理最初把 localhost 请求改写为 502；随后用 `NO_PROXY=127.0.0.1,localhost` 重启同一隔离候选消除了该环境因素。最终裁决不采用代理阶段结果。
- CUA 会在鼠标位置绘制紫色指针光晕；人物肤色结论只使用把指针移到窗口左上角后的帧，未把光晕误判为产品色偏。
- Hover 截图包含该 CUA 指针光晕，因此仅能证明命中区域与可见状态，不把光晕当作产品 hover 视觉。
- 成功结果计时项未覆盖是 P1-2 的直接后果，不是独立环境失败，也不因此虚构额外缺陷。
- 本轮未读取或评价实现代码，未修改产品代码或 DMG。
