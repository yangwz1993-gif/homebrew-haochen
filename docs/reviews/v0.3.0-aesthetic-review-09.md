## 产品问题

### P1 — 左侧屏幕边缘的气泡尾尖与人物严重脱节

- 最短复现：把人物拖到屏幕最左缘 → 点击人物唤起输入。
- 实际：气泡为避免裁切向右展开，但尾尖仍固定在气泡右下，人物在左下；视觉上像指向完全不同的对象。
- 测量：证据 12 中尾尖中心 x≈693 px，人物可见像素水平中心 x≈82 px，偏差约 **611 px**；尾尖 apex 与人物顶部垂直间距约 14 px。
- 预期：边缘翻转/重定位时尾尖应随人物锚点移动，水平偏差应处于可感知连接范围（建议 ≤12 px），同时保持气泡不出屏。
- 影响：破坏人物与对话的空间归属，用户会直接认为浮层错位或 UI 损坏。
- 严重度：**Major / Gate blocker**
- 置信度：**高**（有效隔离环境，实际拖拽复现并同帧测量）
- 复验点：左上、左中、左下三处；输入/处理中/短结果/长结果四种高度；分别校验尾尖 x 与人物中心 x。
- 截图：**12**（对照正常态 **01**）

### P2 — 无凭据错误态的“重试”没有任何可感知反馈

- 最短复现：无凭据环境提问 → 出现 API Key 错误 → 连续点“重试”三次。
- 实际：每次点击后按钮、文案、状态、计数和动画均无变化；第 1 次点击后持续观察超过 8.12 s 仍无 AX 或视觉变化，第 2/3 次也相同。
- 测量：三次点击动作捕获约 1.04 s、1.05 s、1.02 s；零次出现 disabled、spinner、“正在重试”、新时间戳或失败次数。
- 预期：点击后立即显示可见的进行中反馈；重新失败时刷新状态、时间或次数，明确告诉用户点击已生效。
- 影响：用户无法判断点击是否被接收，容易反复点击、怀疑卡死，也不清楚问题是否重新检查过。
- 严重度：**Major / Gate blocker**
- 置信度：**高**（三次连续复现；环境 engine 精确指向 error 隔离目录）
- 复验点：断网、无 Key、格式错误三类；检查按钮按下态、禁用态、结果刷新及键盘触发。
- 截图：**09**；完整历史状态见 **10**

### P3 — 多个短会话在侧栏都叫“新会话”，历史不可辨认

- 最短复现：连续新建会话并分别问短问题 → 从菜单打开普通完整对话。
- 实际：侧栏出现多个相同的“新会话”；已有自动标题还会被截成 `桌面应用本地保存少量配置，SQ` 或带突兀末尾标点的片段。
- 测量：证据 08 中同屏有 **3 个完全相同的“新会话”**；侧栏有效标题宽度约 300 px（Retina），长标题无悬停说明或第二行。
- 预期：会话提交首条问题后生成可区分标题；截断采用省略号，并提供选中态/完整标题提示。
- 影响：用户无法可靠找回数学题、是非题等短会话，历史导航失去可用性与可信度。
- 严重度：**Major**
- 置信度：**高**
- 复验点：1–5 字短问、仅符号问题、创建后立即关闭、重启 App 后标题是否更新。
- 截图：**08**，普通窗口对照 **03**

### P4 — 最大化后布局没有响应式利用空间，形成巨大空洞

- 最短复现：菜单“打开对话” → 点击绿色窗口按钮最大化。
- 实际：用户消息仍贴最右、回答卡仍贴左侧窄列；中央大面积空白，底部输入框却横跨几乎全屏，视觉重心断裂。
- 测量：2940×1912 px 证据中，主要历史内容集中在顶部约 470 px；中央约 **1600×1050 px** 连续空白。输入框宽约 1500 px，而回答卡宽仅约 360 px。
- 预期：设置合理的居中内容容器与最大宽度；大屏时保持消息阅读列、侧栏和输入区对齐，避免两端漂移。
- 影响：最大化不增加阅读价值，反而让对话关系难追踪、页面显得未完成。
- 严重度：**Moderate / Gate blocker under aesthetic criteria**
- 置信度：**高**
- 复验点：980×708、1440×900、2940×1912 三档；比较消息列、输入列与中央空白比例。
- 截图：**08**

### P5 — 明确的输出格式/长度约束被忽略

- 最短复现 A：问 `2+2 等于几？只给答案。`；实际 `等于 4。`，不是纯答案 `4`。
- 最短复现 B：粘贴 216 字中文并要求“一句不超过三十字”；实际摘要为 **41 字**，超出 11 字。
- 测量：数学小结果 4 个可见字符加标点；长摘要 41 个汉字/标点字符，完成约 51.8 s。
- 预期：严格遵守用户明确、低歧义、易验证的格式和长度约束。
- 影响：削弱用户对“简短回答”能力的信任；会破坏下游复制、通知和受限展示场景。
- 严重度：**Moderate**
- 置信度：**高**（两类明确约束均出现偏差）
- 复验点：`只给数字`、`只回答是或否`、`≤10/20/30 字`；对小结果与详情分别计数。
- 截图：**07**；长输入布局见 **11**

## 环境问题与证据不足

- **启动隔离校准（环境问题，已排除）**：前两次 CUA/LaunchServices 激活未继承临时环境，engine 落到默认 home。所有相关截图已重命名为 `INVALID-*`，最终结论只来自随后经 `ps` 精确核验的 valid/error 进程。
- **长中文耗时归因（证据不足）**：51.8 s 是真实用户等待，但单次样本无法区分模型供应商、网络与 App 调度；本报告仅把它记录为体验风险，不把时延单独作为门禁 blocker。明确的 41 字超限则是可验证的产品输出问题。
- **读屏“同意”路径（证据不足）**：同意会读取当前窗口并可能将屏幕内容传给模型；未获得针对具体屏幕数据和目的地的动作时确认，因此只验证了两次拒绝路径，未更改 macOS 权限。
- **Reduce Motion（证据不足）**：切换系统辅助功能设置需要动作时确认，本轮未执行，也不推断产品动画行为。

## 通过项

- 常态右下位置的气泡、尾尖与人物锚点非常准确，水平偏差约 1 px，垂直留白约 18 px。
- 输入、处理、摘要、详情、继续问、收起与菜单普通完整对话的主链路均可达。
- 详情的“结论 / 依据与细节”层级清楚；SQLite/JSON 回答可读且建议合理。
- 模糊请求会先澄清，没有观察到无关文件、命令或读屏动作。
- 停止态明确说明“停止前生成的内容已经保留”，并可继续发新问题。
- 无凭据错误文案明确指向 API Key 与设置；设置页的凭据输入是 secure text field，未显示任何密钥。
- 读屏前有独立同意/拒绝界面，拒绝可用且未触发系统权限修改。

## 复验门槛

只有以下条件全部满足，才建议重新考虑 PASS：

1. 左/右/上/下边缘所有核心气泡状态的尾尖均稳定锚定人物，且同帧水平偏差处于可感知连接范围。
2. 每次错误重试立即出现可见反馈，并在失败后刷新可核验状态。
3. 已提交的会话不再长期保留无法区分的“新会话”标题。
4. 最大化布局采用一致的阅读列与输入列，不再出现大面积失衡空洞。
5. 明确的数字、是非与字数限制能被稳定遵守。
