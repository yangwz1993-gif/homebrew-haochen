### 明显瑕疵

1. **详情页停止生成后没有“已停止 / 未完成”语义，半截正文看起来像完整回答。**
   - 在详情页长回答生成中点击“停止生成”，按钮恢复为“发送”，回答仍使用普通“结论 / 依据与细节”卡片。
   - 一次停在“不确定度乘积有一个下限 Δ”，复验又停在“物质能量决定时空的弯曲，时空”，均无中止标记、弱化样式或继续生成入口。
   - 桌宠气泡本身会正确显示“已停止 / 我停下来了 / 查看已有内容”；但进入详情后这一状态丢失，造成同一事件两套不一致语义。
   - 证据：[Phase A 截断](./assets/v0.3.0-aesthetic-review-11/08-stop-incomplete.jpg)、[Phase B 详情截断](./assets/v0.3.0-aesthetic-review-11/19-detail-stop-unmarked.jpg)、[桌宠正确中止态](./assets/v0.3.0-aesthetic-review-11/21-pet-stop-marked.jpg)。

2. **停止后的最近历史指代错误。**
   - 中止现代物理长回答后立即追问“继续，用一句话告诉我刚才停在哪里”。
   - 可见上一条正文停在广义相对论“时空”，回答却称“刚才我们聊到怎么快速开始一天的工作”，把更早话题误当作刚才。
   - 这会直接破坏连续对话可信度，且发生在用户最需要恢复中断上下文的场景。
   - 证据：[停止后历史错指](./assets/v0.3.0-aesthetic-review-11/20-post-stop-history-wrong.jpg)。

3. **三个已完成首问的新会话仍全部显示“新会话”，无法区分。**
   - 通过菜单栏连续创建 3 个会话，首问分别为彩虹、两种咖啡、7 天 Python 计划，第三个为长首问；均已得到回答。
   - 打开带侧栏的完整会话后，三行标题仍全部为“新会话”；等待后没有刷新。
   - 因没有有效标题，本轮也无法进一步判断“标题是否会被二次改成突兀冒号”。
   - 证据：[三会话首次观察](./assets/v0.3.0-aesthetic-review-11/25-three-sessions-generic-titles.jpg)、[等待后仍未命名](./assets/v0.3.0-aesthetic-review-11/26-three-sessions-still-generic.jpg)。

### 轻微建议与证据限制

1. **完整会话错误卡缺少内联恢复按钮。** 错误文字明确要求打开设置，但完整会话里只有红色文本卡；“检查设置 / 重试”只在桌宠气泡中可见。用户仍可通过菜单栏进入设置，路径不死，但最好在错误卡内直接提供操作。

2. **会话管理入口偏隐蔽。** 桌宠右键无菜单；会话入口位于菜单栏第二个“haochen”菜单的“打开对话”，首次用户不容易想到。完整会话侧栏本身有显式“+ 新会话”，进入后清楚。

3. **重命名 / 删除入口证据不足。** 会话行是自绘控件，没有暴露为 CUA AX 元素，CUA 也无 hover API；坐标右键返回 `AXError.notImplemented`。因此不能证明入口不存在，也不能验证删除确认安全性。

4. **Dock 像素级安全间距证据不足。** 人物被向底边外继续拖动后，App 截图仍完整显示 96×96 全身；输入、处理中、结果气泡均置于人物上方且尾巴向下。但 CUA 只裁切 App 窗口，无法把 Dock 与人物放入同一帧，不能给出同屏像素测量。

5. **肤色可做极小幅调色验证。** 成年工程师造型、发型、眼镜、卫衣和动作都成立，也没有与气泡冲突；肤色略偏高饱和橙色，蓝色悬停光会强化橙蓝对比。建议仅做小幅降饱和 A/B，不重做人设。

## 已通过的主要门禁

- 含糊问题会先澄清，没有乱猜或乱用工具；处理中“收到，我接住了”简短自然。
- 桌宠与完整会话中，`⌘Enter` 都只换行，`Enter` 才发送；三行历史气泡逐行保留原换行。
- “只回复‘好’”最终可见“好”、继续问与详情入口；纯文本在详情中归入“结论”。协调者提供的生命周期为 `20.025 秒`，满足至少 15 秒的 transient 目标。
- “最多两点”严格输出两点。
- 读屏前出现“读吧 / 不读”确认；选择“不读”后工具历史显示“未执行 · 未获授权”，最终明确表示没有读屏、没有删除文件、不会假装完成。
- 左、右、顶部、底部气泡方向正确；最大化后保持居中窄列，恢复稳定。
- 无凭据错误态中文清楚：说明 API Key 无效或格式不正确并建议打开设置；无堆栈、路径、内部异常名或凭据泄露。
- 连续 3 次重试都会刷新为“刚刚完成第 1 / 2 / 3 次重试，仍未连接成功”；快速失败下未捕获到中间加载或禁用态，但计数与完成反馈明确。
- 错误态完整会话保留红色错误卡；设置页明确显示“当前凭据验证失败”，安全输入框为空，新 Key 先验证后保存且失败不覆盖当前 Key，恢复路径有效。

## 发布建议

先统一 stopped 状态的数据与呈现：详情卡必须显式标注中止，后续对话也必须把最近中止回合作为“刚才”。同时让首轮完成后生成的会话标题可靠落地并可区分。修复这三项后，再用真实 hover 环境补验重命名 / 删除确认，并补一张 Dock 与人物同帧的安全间距证据。
