# v0.3.4-rc.8 读屏目标、进度与纯性能优化

日期：2026-09-11。候选包，仅本机工程验证；等待所有者验收。不安装、不卸载、不重置权限、不修改钥匙串、不发布 Homebrew。

## 问题与处理

- 用户已切到新网页后再问，却收到“目标窗口已不可访问”。历史日志中失败绑定耗时约 11.7～12.4 秒；留存的目标记录混合了文章标题与 BBC 首页 URL，而之后检查同一 PID、窗口仍可访问。此证据不能证明用户在读取期间切走，旧错误文案的推断不成立。
- Chromium 窗口级 AXDocument 可能滞后于当前网页。网页身份改用当前 AXWebArea 的 AXURL；原生 file: 文档身份保持文件路径。新增确定性测试复现“窗口仍报旧 URL、页面对象已是新 URL”，不取消身份校验，不以标题模糊匹配冒充同一页面。
- 区分页面身份校验失败、窗口匹配失败、权限不足；不再把“匹配失败”解释成用户关窗。模型约束同样禁止编造失败原因。
- 读取器由每次启动 onefile 改为 onedir + 每个引擎一个私有管道服务。预热仅加载程序，不读取窗口、正文，不触发权限请求；bind 仅元数据，明确同意后的 read 才采集正文。完成、拒绝、过期后释放目标；采集中取消则终止工作进程，下轮重新启动。
- 原图仅做同一轮相同 URL 下载去重，结果仍映射回所有对应图片块；不使用跨轮图片缓存、不少读正文、不减少原有 15 张选择上限、不改变原有图片字节/截图处理规则。

## 可见状态

1. 确认目标 / 等待本次阅读授权。
2. 正在固定画面，请暂勿切换。
3. 画面已固定，可以切换；正在获取原图。
4. 正文及本轮图像获取处理结束，工具成功后才显示绿色“✓ 已读取，可以切换”。失败不显示成功。

短气泡和完整会话均接入真实工具事件，不用模拟百分比。读屏工作气泡宽度 420 pt，避免将指导文字塞入原有 196 pt 思考气泡。短气泡成功标记约 2.5 秒后移除，最终回答到达可替换该工作态。日志仅增加阶段、工具 ID 和耗时，不记录屏幕正文或图片。

## 原生安装包实测

使用本轮新建的公开 BBC 测试标签，通过真实 macOS AX/窗口采集与原图下载，不调用用户模型、不读取凭据。测试后关闭本轮两个新建标签，原有标签保留。

| 场景 | 绑定 | 固定正文/画面 | 完整获取 | 信息量 |
| --- | --- | --- | --- | --- |
| BBC 文章 A，连续三轮 | 106 / 25 / 29 ms | 251 / 240 / 236 ms | 2737 / 2429 / 2369 ms | 每轮 151 文本块、10974 字符、8 张原图、辅助截图 |
| 同标签站内切到文章 B，之后不切屏，连续两轮 | 112 / 25 ms | 274 / 278 ms | 3990 / 3860 ms | 每轮 180 文本块、13966 字符、12 张原图、辅助截图 |
| 绑定文章 B 后切去另一个标签再采集 | 106 ms | 210 ms | 4799 ms | 仍是文章 B 的 180 文本块、13966 字符及 12 张原图，没有混入新标签截图 |

旧安装版单独执行权限检查即耗时约 9780 ms；新版首次服务启动实测 2224 ms，后续另启进程实测 132～191 ms，同一服务内后续请求无需重启。系统冷缓存、签名校验与网络会影响时间；这是读取器分段测量，不是整轮模型回答延迟，也不是严格控制网络变量的旧新 A/B 加速比。

源代码服务对文章 A 另测三轮，同样保留 151 块/10974 字符/8 原图/辅助截图，与打包读取器信息统计一致。

### 明确边界

固定画面前切走，保留的原页面对象仍可读取正文及 URL 原图，但不能拿当前新标签的窗口截图补旧内容。测试中页面有 1 个无原图 URL 的图像块，切走后的结果因此没有辅助截图；这是避免混页的边界，不是提速而降质。按提示等到“画面已固定”后再切换，已采集的文本与辅助像素不依赖后续前台窗口。

本轮没有宣称所有第三方 App 均可后台完整读取。沿用原生窗口、文档文件、图片/PDF 路径及安全失败的既有能力；本轮新增原生实测集中于用户失败的复杂浏览器页面。

## 回归与交付

- 真实打包引擎 + 本地合成模型/读取器：成功和失败均进入本轮模型上下文；真实 tool_execution_update 顺序为 binding → bound → capturing → snapshot，tool_execution_end 才发成功。
