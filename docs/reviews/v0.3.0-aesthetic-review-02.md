# v0.3.0 独立审美用户验收（第 2 轮）

验收对象：`27d1871` 构建的 `haochen-0.3.0-dev.1.dmg`。

验收方式：验收者未阅读代码、路线图或已知问题，先自由盲测，再按状态矩阵检查，最后才
查看用户提供的旧版小窗截图。验收者只从用户视角操作构建产物，不参与开发。

## 结论

本轮不通过。小窗输入态的大面积无意义留白已经确认修复，但仍有一个明显的错误恢复
瑕疵；由于测试包未能使用有效密钥，其余动态状态未形成完整的真实包证据，不能据此
宣布版本可交付。

## 已确认改善

### 旧截图的大面积留白未在当前构建复现

- 状态与操作：启动开发包，单击人物进入空输入态；盲测完成后才对照用户截图。
- 旧截图：可见气泡内连续空白至少约 `144px`，约占可见气泡主体的 `56.3%`。
- 当前构建：输入态气泡约 `400 × 154` 逻辑像素，最大连续无内容区域约 `13px`，约占
  主体 `9.3%`。
- 当前证据：`/tmp/haochen-R2-LISTENING-empty.png`（验收机临时证据）。
- 判断：用户指出的“输入区上方大块空白”已修复，当前构建未复现。

### 输入态人物与气泡关系基本成立

- 人物与气泡同时可见；尾巴能指向人物。
- 当前联合画面约为 `800 × 308` 物理像素；按逻辑像素折算，尾巴与人物中心水平偏差
  约 `6px`。该测量略高于门禁 `4px` 基线，但受 Retina 截图缩放和人工定位影响，暂不
  单独判为明显瑕疵，下一轮使用程序输出的几何数据复验。

## 问题

### I-01 人物在 Retina 屏上仍有明显低分辨率感

- 证据编号：R2-LISTENING-empty。
- 状态与操作：启动后观察人物，再单击唤起输入框。
- 实际：人物轮廓和五官呈明显块状像素，和气泡的细腻圆角、文字渲染不在同一精度层级。
- 测量：当前截图为 Retina 物理像素，人物局部边缘仍能看到明显大像素块。
- 预期：保留原有人物风格，但在 Retina 尺度下轮廓、眼镜和肤色边缘应清晰稳定。
- 影响：不阻断操作，但会削弱成品感。
- 严重度 / 置信度：精修项 / 高。
- 复验点：在 Retina 屏上分别截取 `100%` 与放大后的待机人物，检查边缘是否仍像低清放大。

### I-02 从错误页进入设置后，关闭设置会丢失错误上下文

- 证据编号：R2-ERROR-settings-return。
- 状态与操作：配置无效开发密钥并发送问题 → 出现错误卡 → 点击“检查设置” → 关闭设置。
- 实际：约 `1.46s` 后出现错误；“检查设置”约 `1.04s` 后打开设置。关闭设置约 `0.89s`
  后，小窗不再显示；再次点击人物只得到空输入框，先前错误原因和“重试”入口丢失。
- 预期：设置关闭后回到原错误卡，用户可以看见原原因并直接重试；若错误已解决，再由重试
  进入新状态。
- 影响：恢复路径断裂，用户无法确认自己为什么进入设置，也无法沿原动作继续，属于普通
  用户会直接感知的交互瑕疵。
- 严重度 / 置信度：明显瑕疵 / 高。
- 复验点：错误卡 → 检查设置 → 关闭设置，应恢复同一张错误卡且“重试”可用。

## 本轮未覆盖

验收环境中的开发 Keychain 没有有效密钥，构建包又不接受 mock 模式，因此未能可靠到达
`ACKNOWLEDGING / PERCEIVING / ACTING / COMPOSING / PRESENTING / CANCELLED` 六种状态。
下一轮必须使用隔离数据目录并安全引用现有有效 Keychain 服务，至少完成一次真实问答，
同时用 mock 联合证据补齐权限、工具与停止等难以稳定触发的状态。

验收期间发现系统中同时存在仓库开发版、源码 mock 版和 `/Applications/haochen.app`，容易
选错目标。下一轮应在启动前确认进程路径和数据目录，只验收指定构建产物。
