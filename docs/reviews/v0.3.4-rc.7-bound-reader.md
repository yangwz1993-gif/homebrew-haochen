# v0.3.4-rc.7 固定对象阅读修复

本轮处理 `0911-2017验收.md` 与随后确认的通用窗口阅读流程。候选包交由所有者验收，不自动安装、不清除配置/权限/日志，不更新线上 Cask。

## 根因与修改

1. 初始化模型配置的正常重启曾复用崩溃恢复提示，宠物隐藏时也会弹出“连接已恢复”。Supervisor 现在区分 configuration/recovery；配置流程的成功与失败只在发起的表单呈现，真实崩溃仍保留恢复反馈。
2. rc.6 只保存 PID、窗口 ID 和指纹，获准后才启动读取器并重新找窗口；屏幕切换与 onefile 启动延迟之间存在竞态。现在读取器在阅读确认前完成仅元数据绑定，持有原生窗口/AXWebArea 对象，等 stdin 明确授权后立即读取。拒绝、取消、超时或父进程结束均释放对象，不提前读取正文或截图。
3. AX 与 CG 窗口匹配支持非当前桌面的窗口；读取期间不再按前台或几何位置重选对象。网页页面对象和宿主窗口分离，切换标签后可继续读取仍存活的原 AXWebArea。若宿主已展示新标签，不把它的截图拼到旧页面正文上。
4. 本地文档来源由 AXDocument 的 file URL 绑定，仅元数据阶段记录文件身份；授权后按需读取单个文件。支持 UTF-8 文本/代码、带文字层 PDF（最多 100 页）及 PNG/JPEG/GIF/WebP 原图，4 MB 上限。检测文件被替换/修改；已保存文件版本与未保存窗口内容明确区分。原图字节保留，不用预览窗口截图冒充原图。
5. 当前失败的工具调用原来没有进入 currentReads 集合，被 context 钩子误删为历史快照；现在在调用入口标记，失败和拒绝也归属本轮。通过引擎正式 tool_result 钩子设置 isError，修复原来只在 execute 返回对象放 isError 而引擎忽略的契约错误。
6. 阅读确认缩短为应用与有限长度标题；原生浏览器测试还发现 AXHeading 的 AXValue 是标题级别而非标题正文，已修正并补回归。跳过密码输入节点。

## 边界与验收重点

- 不宣称所有应用都有 URL/文件地址。普通应用走保留的 AX 对象；没有真实内容接口时仍需图像辅助和对应权限。
- 页面对象如果被应用销毁，或正文采集期间确实变化，会明确失败，不改读新页面。关闭旧标签、同 URL 的应用内部路由、虚拟化聊天列表仍需用户场景验收；不保证任意后台页面永久可读。
- 本轮不偷偷启用浏览器远程调试、不接管用户浏览器登录态，也未新增 HTTP 抓取来冒充当前网页 DOM。记录的 URL 用于身份校验；需要额外浏览器连接器的场景另行对齐。
- 本地文档接口不包含未保存编辑。复杂 Office 格式仍走 AX，不将“不支持磁盘解析”说成已支持全部文件。扫描 PDF 需要图像阅读；本轮新增的 PDF 文件适配器只读文字层。
- 用户重点验收：初始化无孤立恢复气泡；同意后立即切应用/窗口/标签仍读原对象；拒绝/关闭不读取；新一轮问当前页面不沿用旧内容；读失败时得到具体原因而非“历史快照已封存”。
