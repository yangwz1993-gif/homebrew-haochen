# haochen 交互规范（Interaction Spec）

> 版本：v1.0 ｜ 作者：产品 ｜ 用途：P3 三 UI 并行开发前的**交互约定**，与 `visual-spec.md` 配套。定义用户与 haochen 交互的**状态机、关键路径、元规则**，保证三前端手感一致、体验达标。
> 原则：**最大化用户体验**——感知可见、行动可见、先详答后结论、先问再动、随时可打断、不打扰。

---

## 0. 交互元规则（最高优先级，所有 UI 遵守）

1. **感知可见**：haochen "在看/在想/在动" 时，一定要让用户感知（状态提示 + 桌宠姿态），绝不默默读屏。
2. **行动可见**：每次工具调用（读屏/命令/文件）都以**工具卡**呈现，用户能看懂它在干什么，可展开、可暂停。
3. **先详答后结论**：先给完整的依据/步骤/产物（L2 详答），最关键的结论（L1 短结）收在最后。
4. **先问再动**：不确定 / 需要权限 / 会动用户文件 / 读屏前，先确认再执行。
5. **随时可打断**：Esc / 点空白可收起；不打断用户当前心智负担。
6. **连续性**：对话上下文不丢，气泡 ↔ 窗口同一会话，追问无缝继续。
7. **不打扰**：无需用户注意时安静待着（idle）；只在"需要确认/出结果"时轻提示唤起。

---

## 1. 核心状态机

```
                  ┌─────────────────────────────┐
                  ▼                             │
    [IDLE] 桌宠安静待着（idle）─────────────────┤
        │                                       │
        │ 双击 / ⌃⌥P 唤起                       │
        ▼                                       │
    [AWAKE] 气泡淡入（动态对话流起点）            │
        │                                       │
        │ 用户输入问题                            │
        ▼                                       │
    [PERCEIVE] ↓ 感知：需读屏？                 │
        │  "我正看一下你的屏幕…" (color-info)    │
        │  桌宠"眼睛对准屏幕"姿态                 │
        │  需要权限/不确定 → 先问（读吧/不读）    │
        ▼                                       │
    [THINK] 思考（桌宠 thinking 姿态）           │
        │  "正在想…"                            │
        ▼                                       │
    [ACT] 工具执行（读屏/命令/文件）             │
        │  每步以工具卡呈现，可展开/暂停          │
        ▼                                       │
    [CONVERGE] 收敛                            │
        │  L2 详答（原因/步骤/产物）           │
        │  L1 短结（一句话结论，收在最后）      │
        │  流式输出 + 工具卡                    │
        ▼                                       │
    [AWAKE] 可继续追问 ────────────────────────┘
        │
        │ Esc / 点空白 / ✕
        ▼
    [IDLE]（结论保留在会话，可稍后回看）
```

> 任何状态都可被打断（Esc 收起）；AWAKE 中失焦**不**自动收起（参考"一直挂着"）。

---

## 2. 唤起 / 收起

| 操作 | 触发 | 说明 |
|------|------|------|
| 唤起 | 双击桌宠 / 全局快捷键 `⌃⌥P`（Ctrl+Option+P，与上一版一致） | 气泡从桌宠方向淡入+上滑 |
| 收起 | Esc / 点空白 / 右上 `✕` | 淡出，指向桌宠 |
| 失焦 | **不自动收起** | 保持挂着，避免误伤 |
| 打断 | 任何时刻 Esc | 停止当前生成/工具，保留已产内容 |

---

## 3. 输入交互

- **回车 `⏎`**：发送。
- **⌘ `⏎`**：换行（与主流对话产品一致）。
- **可打断**：正在生成时，输入框上方出现"停止"按钮；点它即中断。
- **不被覆盖**：生成期间仍可输入新内容，回车即追加新问题。

---

## 4. 感知 / 确认（关键体验）

### 4.1 读屏前
- 触发读屏时：气泡顶部出现**感知提示**「我正看一下你的屏幕…」（`color-info`，弱化）+ 桌宠"眼睛对准屏幕"姿态。
- **先问再动**：首次或不确定时，弹**确认**「要我读一下你的屏幕吗？」→ 明确按钮 **“读吧” / “不读”**（主按钮实心，次按钮描边）。用户确认后才读屏。
- 页面变化检测（沿用）：若屏幕内容变化，提示后重新确认。

### 4.2 工具执行
- 每步工具调用渲染为**工具卡**：图标 + 工具名（读屏/命令/文件）+ 状态（运行中/✓/✗）+ 摘要。
- 工具卡**可展开**看详情（命令全文、读屏片段、产物路径）、**可暂停/继续**。
- 失败时工具卡显示错误，给出**重试**入口。

---

## 5. 对话流（动态气泡）

- 气泡**不是固定输入框**，而是**动态对话流**：输入 → 思考 → 结果**逐条弹出**（带轻动效，见 `visual-spec.md` §5），像真实对话在发生。
- 用户消息、感知提示、L1、L2、工具卡按时间顺序排列，各自成"气泡块"。
- 流式文字：打字机 + 工具卡动态插入。

---

## 6. 会话管理

- 侧栏当前会话高亮；可**新建 / 切换 / 删除**；**历史持久化**（重启仍在）。
- **气泡 ↔ 完整窗口共享同一会话**：在气泡聊的，窗口能看到；反之亦然；追问不丢上下文。
- 会话按时间/项目分组（可选），每条会话有标题（自动/可重命名）。

---

## 7. 配置交互

- 配置面板：模型 / provider / API Key / 主题 / 行为开关。
- **改完即生效**（或明确提示"需重启生效"），重启后保留。
- 设置项**少而清晰**（默认值即好用），避免吓到用户。
- 入口：桌宠右键"设置" / 窗口侧栏"设置"。

---

## 8. 权限与生命周期

### 8.1 权限引导（首次运行）
- 首次需**辅助功能**（读屏核心）时：弹引导，指向 `系统设置→隐私与安全性→辅助功能`，勾选本 App。
- 若走截图 OCR 兜底：提示**屏幕录制**授权。
- 引导**步骤化、可跳过**，但读屏功能需授权才可用。

### 8.2 引擎 / 进程
- 引擎随 App 启动；若引擎崩溃/被杀，**App 感知并重启或明确报错**，不白屏。
- 错误信息面向用户可理解，附重试/查看详情。

---

## 9. 无障碍与体验底线

- 文字对比度符合可读性（`color-ink` on `color-bg`）。
- 所有交互可通过键盘完成（回车/空格/Esc/快捷键）。
- 不出现"闪烁/突然跳转"等打扰性动效。

---

## 10. 验收清单（产品侧会在 P4/P6 核对）

1. 唤起直达（≤1s 可输入）；失焦不收起。
2. 读屏有感知提示 + 明确"读吧/不读"确认。
3. 工具调用全部以工具卡可见、可展开。
4. 回答先 L2 详答（依据/步骤/产物），再 L1 结论。
5. 气泡 ↔ 窗口同一会话，追问不丢上下文。
6. idle 安静不打扰；需要时轻提示。
7. 引擎崩溃能恢复或明确报错，不白屏。
8. 首次能正确引导授权辅助功能/屏幕录制。

---
