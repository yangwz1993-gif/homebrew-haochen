# haochen v0.1.8 修复验收点

> 依据：用户真机反馈（2026-08-27 00:42 截图）。给 kimi 实现（resume v0.1.7 会话）。

## 问题：用户问图 → 读不了图（答非所问）
- **现象**：用户在微信图片窗口问「这个男的帅么」，haochen 回复"没看到图：读屏只抓到微信的图片/视频窗口，画面显示不出来"。
- **根因**：read_screen 走的是 **AX 文字读屏**；图片在辅助功能树里只有占位、无文字 → 只拿到窗口标题，没拿到画面。而 **reader 的截屏能力本身是好的**（实测 `--json` 输出 screenshot PNG 约 1.8MB base64，正常）。

## 要做：看图策略（图片问题 → 截屏发多模态模型）
- 在 read_screen 流程加**看图模式**判定：满足任一即走"截屏发图"而不是只读 AX 文字——
  1. 用户问题含看图意图（看图/这张图/帅不帅/评价一下图/图里 等关键词，或消息携带图片附件）；
  2. 前台窗口是图片/视频/预览类（标题含 图片/照片/视频/预览/image/photo 等）；
  3. AX blocks 为空或文本极少（只有标题没正文）。
- 截屏用 reader 现有 screenshot 能力（CGWindowList/整屏，需屏幕录制授权，已具备）。
- 发图沿用 P8 多模态策略（原图优先/尺寸优先级），把截图 PNG 作为图像输入发给模型。
- 若屏幕录制未授权：走授权引导（现有三层防护），不静默失败。

## 验收
- 微信图片窗口问图 → haochen 能描述图片内容（真的看到图）。
- 普通文字问题 → 仍走文字读屏（不滥用截屏）。
- 回归 `tests/run_all_regressions.sh --real` → PASS=7 FAIL=0；补：看图模式触发断言（含图片意图→有截图输入；纯文字→无）。
