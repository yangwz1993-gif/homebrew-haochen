# 模型配置页整改证据（0.6.2-beta.3 追加）

日期：2026-09-16 ｜ 范围：模型目录失联 + 设置页混乱 + 切换不生效

## 问题与根因

| 现象 | 根因 |
|------|------|
| 下拉里没有 deepseek-v4-flash-0731-baidu | 配置迁移只 seed auth.json，从不合并 models.json；运行时目录（~/Library/.../agent/models.json）与模板失联 |
| 很多"已配置"模型但下拉只有几个、页面乱 | 三套重叠展示：下拉 / 清单文字 / 已添加卡片 |
| 切换好像不生效 | 旧设置页下拉**浏览即写盘**：存储的默认（0731）不在运行时目录 → 回显目录第一项 → 用户一动就被写回 settings.json 覆盖（实测 defaultModel 被冲成 kimi-k3） |

## 修复（三件套）

1. **models.json 模板合并迁移**（config_store._merge_template_models）：启动时把模板新增 provider/模型并入运行时目录——只增不改不删（已有条目、用户重排、custom-* 全保留）。
2. **默认值保护**：设置页改为「浏览不写盘，点应用切换才提交」；存储默认不在目录时显示「当前默认·目录缺失」占位项且拒绝应用，绝不静默改写。
3. **设置页按 v4 demo 重构**：一张模型卡（供应商/模型/Key 三行联动）；codewiz 家族（同一把内网 Key 的 codewiz+codewiz-gemini）折叠为一个供应商；Key 区四态（内网托管只读 / 已保存防窥+查看+修改→保存·取消 / 未配置可填 / 自定义端点指引）；删掉清单文字与已添加卡片的连接按钮。

## Red → Green
